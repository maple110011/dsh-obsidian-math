## 1. 一句话定位

Safe 把"验证 LLM 的推理链"从**打一个黑箱分数**改成**逐步提供可检查的证据**：对推理轨迹的每一步，用 LLM 自动生成一条**只判定该步正确性**的 Lean 4 陈述（陈述的**前提 = 该步之前的内容，证明目标 = 该步的结论**），交给现成的自动定理证明器去证；证明器的结果被归约为**四个离散状态**（不需要验证 / 形式化失败 / 形式化成功且证明成功 / 形式化成功但证明失败），再把这些状态序列聚合成一个"**回顾性（retrospective）**"分数，与 PRM 的"**前瞻性（prospective）**"分数相乘。

---

## 2. 问题与动机

- **失败模式**：CoT 已成为调动 LLM 推理能力的事实标准，但 CoT 里的**幻觉极难检测**，而在数学这类领域**一处小错就会破坏后续生成与最终答案**。
- **现有做法的缺陷（论文的核心批判）**：PRM / self-consistency 一类方法**把验证器当成不透明黑箱**，只输出分数而**不给出可检查的证据**（`do not provide checkable evidence for their judgments`），因而**丢掉符号计算与形式验证的好处**，缺乏可解释性、也不提供正确性保证。
- **立论依据**：借 Avigad et al. (2021) 的一句话——"**支持一条数学断言的金标准是给出证明**"。于是把"形式化"用在**验证**而不是"翻译题目"上。
- **两个关键定位（这两个区分决定了它对我们是否有用）**：
  1. **retrospective vs prospective**：形式验证器判的是**这一步本身对不对**（回顾），PRM 判的是"**从这步出发未来能否得到正确答案**"（前瞻，Q-value）。论文把它画成 Figure 1，并强调二者**互补**：形式验证 + 自然语言推理的神经符号组合。
  2. **step-aware**：整条推理轨迹太长、难以直接验证，所以**先分解成更简单的步骤**，只对单步做形式化与证明；论文的观察是**单步有效性陈述的证明难度直观上低于整题**，因此**分布外（OOD）的陈述仍可能落在当代 ATP 的能力范围内**。
- **明确的能力边界（论文自己写的）**：有些步骤**不需要**形式化（吟唱、重复、总结），有些步骤**超出 Lean 4 的表达范围**——Lean 4 能表达数论与代数的关系，但**在几何与组合数学的概念上受限**。

## 3. 记忆结构

这不是记忆系统论文，但它的**分级数据结构**对我们有用：

- **一条推理轨迹的表示**：`A_i = concat(step_i1, step_i2, …, step_i,m_i)`——即一条答案被显式分解成一个**有顺序的步骤序列**，`m_i` 是步数。
- **每步的判定是一个只取四个值的枚举**（`state_ij = step_verifier(step_ij)`）：
  1. **no verification required**（不需要验证）；
  2. **failed formalization**（形式化失败——原因可能是 Lean 4 语言限制，也可能是自动形式化流水线的限制）；
  3. **successful formalization + proof of the statement**（形式化成功且证明成功）；
  4. **successful formalization, but theorem proving failed**（形式化成功但定理证明失败）。
- **关键设计决定：四态而不是分数。** 论文原话是 `instead of providing numerical scores for each step`——它把"每步的数值奖励"明确**换成了离散状态**。这是 Safe 对我们最可搬的一条：**判定结果是可以枚举的，不是连续打分。**
- **一步的信息量被显式量化**：`each state conveys only two bits of information`（4 态 = 2 bit）。论文用这一点解释为什么它必须靠聚合器、为什么它与 PRM 互补。
- **聚合结果**：四态序列（当作 token）喂给一个**极小的 LSTM**（词表大小 4），取最后一步的隐变量经线性变换 + sigmoid → `score_retro ∈ [0,1]`。
- **最终分数**：`score_i = score_retro^α · score_pro^(1-α)`，取 argmax 的那条答案；α 是超参。

## 4. 写路径（固化）

不是写入记忆，而是**"一条推理链如何被固化成可验证的对象"**，值得逐条抄：

1. **采样**：对问题 P 用 **zero-shot CoT** 采样 n 条答案（prompt 的最简形式就是 "Let's think step by step"）。
2. **分解**：把答案切成步骤。探索了两种方式：
   - **启发式规则**：以句号或换行切分。论文自己指出了它的失败：会**切得过碎**，而且**句号可能是小数点而不是句子分隔符**。
   - **LLM in-context learning（优先方案）**：从 PRM800K 训练集里随机取人工标注的逐步数据当 few-shot，要求模型输出 **JSON 数组**，每个元素是一个"逻辑上独立"的步骤字符串。提示词有两条硬约束：**只能切分，即使答案是错的也不得做任何修改**；**必须包含完整解答、不得漏步**。
   - **回退机制**：`We prioritize the LLM in-context learning setting; if the JSON output is not parsable, we revert to the heuristic rules-based approach as a fallback.` ——**首选方案失败时有一个确定性的回退**，这是"轻量 + 稳健"的一个小范本。
3. **每步形式化**（§3.2.1 + 附录 A）：对每步生成一条 Lean 4 定理，**形式化成功与否本身也要过一遍 Lean REPL 以确认语法**。
4. **证明**：把定理交给 ATP（COPRA / DeepSeek-Prover-V1.5）。
5. **并发**：`Verification of these steps can be conducted concurrently to minimize end-to-end latency.`——**步骤之间可并行**（因为每步的验证只依赖它自己的前提与目标）。

---

## 5. 读路径（检索）

不适用（无检索层）。唯一相关的是**上下文构造**：auto-formalization 的 prompt 里带上**问题**与**该步之前已经写出的步骤**（`each step is derived from the previous ones, so the theorem may require referencing information from the question or earlier steps`），few-shot 示例里也演示了"先输出 `False`（不需要验证）的步骤，再输出需要验证的那一步"。也就是说，**被验证的一步不孤立出现，而是带着它的前提链出现**。

## 6. 组织与关系

- **分类维度只有两个**：
  - **按步**（step-level）：四态枚举；
  - **按学科**（附录 B 的第二个 LLM-as-a-judge 提示词）：geometry / number theory / algebra / combinatorics / others 五类，用于统计 FormalStep 的分布。
- **"不需要验证"是一等状态而不是遗漏**：提示词里明确要求模型判"这一步是否简单直观到我确信它不需要验证"，并输出 `False`。这条对应我们记忆系统里的"**这条值不值得形式化/审查**"问题（见 §12）。
- **步骤之间的唯一关系是顺序**（前一步是后一步的前提），没有图结构。

## 7. 维护与自改进

- **状态聚合器的训练数据来自"结果已知"的轨迹**：从训练集里取与测试集规模相当的一小部分（MATH 500 题、GSM8K 1,000 题、CollegeMath 全训练集），让推理模型去答，**把输出与 ground truth 比对**得到轨迹的对错，再用这些轨迹训 LSTM。也就是**用最终答案的对错当弱标签，来学习"状态序列 → 分数"的映射**。
- **数据效率极高**：约 **2,000 条轨迹**（来自 500 题）就够训一个有效的 LSTM 聚合器；论文把它与 PRM800K（约 **800k** 步级标签、**75k** 条解答）和 Math-Shepherd（**445k+** 推理策略）对比。论文的解释是：LSTM 做的是**针对状态序列的模式识别**，不直接处理自然语言。
- **已知的失效条件（对我们很有用的一条负面知识）**：**当正确/错误样本比例严重失衡时，训练有效的 LSTM 很困难**。四个测试模型在 GSM8K 上接近饱和，训练集里几乎没有错误样本，因此 LSTM 学不到错误模式——论文把它当作 GSM8K 上提升有限的原因。
- **论文承认的未解问题（Limitations）**：
  - Lean 4 REPL 的输出与最终评分之间的**相关性相当间接**；
  - 基于 LSTM 参数的评分机制**仍然缺乏完全的可解释性**；
  - **虽然验证是在步级做的，但方法并不提供每一步的精确奖励分**，因为自动形式化与自动定理证明的当前局限**引入了噪声**；
  - 提出的改进方向是：通过系统分析这个紧凑 LSTM 的参数与决策机制，**找出关键的证明步骤**（即用中间验证状态与最终结果的相关性来定位关键步）。

## 8. 验证与质量门控（重点）

### 8.1 逐步验证的完整契约

**输入**（每步一份）：
- 数学**问题** P；
- **该步之前的步骤序列**（作为可引用的信息，也作为定理的前提）；
- **待验证的那一步**。

**输出**（每步恰好一个状态，四选一）：
1. `no verification required`
2. `failed formalization`
3. `successful formalization + proved`
4. `successful formalization + proof failed`

**中间产物（可解释的证据）**：一条 Lean 4 定理陈述（`theorem … := by sorry` 形态，提示词明确要求**不要给证明方法**、用 `sorry` 占位）+ 一份由 ATP 产出的 Lean 4 证明 + Lean REPL 的校验结果。

> 注意这个契约的形状：**"形式化成功与否"与"证明成功与否"被分开报**，所以"我们看不懂/表达不了这条"（状态 2、部分 4）与"这条是错的"（状态 4）在数据上是可区分的——这正是"无法验证时不要假装可信、也不要直接丢弃"的机制形式。

### 8.2 形式化的粒度（§3.2.1，这是全文最可搬的一段）

- **不是翻译整题，而是构造一条"支持该步"的定理**：论文的例子是——当推理模型做不等式变换时，**用变换前的不等式作前提、变换后的不等式作证明目标**。
- 提示词（附录 A）给出的判据是三段式：
  1. 若该步简单直观、确信不需要验证 → 输出 `False`；
  2. **但所有数值运算都必须验证，不论多简单多直观**（`you need to verify ** ALL NUMERICAL ** operations, no matter how simple or intuitive they may seem`）；
  3. 若该步有"不很直观的跳跃"、可能含幻觉 → 给出能验证该步的 Lean 定理；**若这条 Lean 定理可以被证明，则该步正确、不含幻觉**。
- 其他硬约束：定理**必须符合 Lean 4 语法**、**避免用自然语言描述性质**、**不得给出证明方法**、**只输出定理或 `False`，不得输出其他内容或预测下一步**。
- 提示词特意加入了 **Lean 3 与 Lean 4 的语法差异**说明（`Lean 4 is not backward compatible with Lean 3`；类型常量改为 UpperCamelCase 如 `Nat`/`List`；lambda 用 `=>` 而不是 `,`），因为观察到**LLM 会把 Lean 3 与 Lean 4 的语法混起来**。
- **一致性核查也是一条独立工序**（附录 B）：用 LLM-as-a-judge 判"形式化陈述与自然语言步骤的语义对齐"，三档 `good / fair / poor`。判词写得很直白：对齐则"证明该 Lean 陈述即在数学上验证了最后一步的正确性"，不对齐则"该 Lean 陈述与最后一步的正确性无关"。**这条工序承认了"语法正确 ≠ 语义忠实"**（论文在 §1 也点名 `syntactic correctness (i.e. successful compilation) is insufficient`，引 Liu et al. 2025）。
- **失败是可观测的**：一致性评价结果是良好 **24,938（80.9%）** / 一般 **138（0.4%）** / 差 **5,733（18.6%）**，共 30,809。论文拿它与 FormL4 的 72% 与 Lean Workbook 的 93.5% 对照，并说明**它选择 LSTM 聚合而不是直接拒绝所有不可证步骤，因此对不完美的一致性应当稳健**。

### 8.3 定理证明模块（§3.2.2，成本与预算的取舍）

- 使用现成 ATP：**COPRA**（GPT-4o 驱动，agent 式）与 **DeepSeek-Prover-V1.5**（7B）。
- **默认策略是 DeepSeek-Prover-V1.5 + sample budget 16 + 不用 MCTS**。理由：整题证明常用树搜索与上千次搜索预算，但**逐步验证的定理数量极大**，那种成本不实际。
- 论文的关键经验断言：**用 sample budget 16，足以证明 FormalStep 中超过 80% 的陈述**（§3.2.2 与 §5.1 两处都写）。
- 低算力下 **DeepSeek-Prover-V1.5 显著优于 agent 式的 COPRA**（附录 H）。COPRA 因为依赖 GPT-4o 成本高得多，**只在随机选的 500 条子集上测**，而 DeepSeek-Prover-V1.5 在**全部 30,809 条**上测。
- **一个诚实的成本承认**（§5.4）：`If we reduce the maximum number of ATP attempts from 16 to 8 — while still achieving a proof success rate exceeding 80% — the average number of theorem proving attempts can be further decreased to 2.67.`

### 8.4 噪声与聚合：为什么必须有聚合器（§3.3）

- 论文明确列出**证明失败的两个额外来源**（即在"步骤真错"之外的假失败）：
  1. **自动形式化流水线可能产出看起来合理但错误、因而不可证的陈述**，而原步骤本身是对的；
  2. **陈述正确且可证，但 ATP 在受限采样预算内证不出来**。
- 结论：`the four states provided by the step verifier are inherently susceptible to noise`；因此**通过聚合来缓解噪声，而不是逐态硬判**。
- 聚合器：**LSTM，词表大小 4，2 层，hidden 64**，batch 32，lr **0.0001**，**200 epochs**；最后隐状态线性变换 + sigmoid。
- **为何是乘法融合（附录 D）**：设计原则是"**任一组件给出强否定信号时，合成分数必须显著下降**"。消融（Table 4，Llama3.1 / MATH-500）：
  | 融合方式 | MATH BoN@5 |
  |---|---|
  | LSTM only | 55.1 |
  | PRM only | 55.2 |
  | Weighted Sum | 59.6 |
  | **Weighted Mul（Safe）** | **60.0** |
  | Min | 57.0 |
  | Max | 58.2 |
- **状态分布与正确率的定量关系**（附录 E）：**43,652 步里 30,809 步（72.2%）被自动形式化成合法 Lean 4 陈述；其中 25,017 条（81.2%）被 DeepSeek-Prover-V1.5 证明成功**；最常见的状态是 `Proof Successful`。**"Proof Successful"的步骤最终答对的概率是 56.7%，而"Proof Failed"的步骤是 40.4%**——论文随即指出，由于自动形式化与自动定理证明引入噪声，**不能直接据此判断整条轨迹的正确性**。

### 8.5 拒绝/失败的"反馈内容"

Safe 与传统验证器的最大差别：**它不返回"拒绝 + 理由"，而是返回"一份可读的形式化陈述 + 一份形式化证明"作为证据，或者一个四态标签。** 论文把这一点当作主要卖点（`interpretable and verifiable evidence`）。**代价**是：它**不给每一步精确的奖励分**（Limitations 明说），而且**这个证据链是二值的（证出来了 / 没证出来），不提供"哪里错了、怎么改"**。

> 对我们的直接含义：Safe 提供了**"把无法判定显式编码成状态"**的范本，但**不提供 repair hints**——后者要从 Danus 借（见跨篇汇总）。

## 9. 成本 / 安全 / 隐私

- **推理成本（§5.4）**：每一步最多 **3 次自动形式化尝试**、最多 **16 次定理证明尝试**，**每次尝试都是一次 LLM 查询**。实际平均：**约 1.02 次自动形式化 + 6.97 次定理证明**。
- 降到 8 次上限仍 >80% 成功率，平均 ATP 尝试降到 **2.67**。
- **与 PRM 的对比结论**：`the LLM queries of our single-step validation is approximately 4–8x greater than that of PRMs.` ——即**安全性的成本是 PRM 的 4–8 倍查询量**。
- **建模成本**：只用 2,000 条轨迹训 LSTM，不需要 PRM800K 规模的标注。
- **scaling 的两种策略（Figure 4）**：对**强模型（GPT-4o、Llama 3.1）**，把算力花在**验证每个样本**上更划算；对**弱模型（Llama 3.0）**，采样质量本身差，**增加样本数 + 用更弱的 RM** 仍然有效。
- **明确的负面结论**：`in some instances, when verification costs are similar, the performance gains may not be significant`（当验证成本相近时，收益可能并不显著）。
- **RL 场景的摩擦**：论文理论上认为 Safe 可兼作训练期的 reward model，但**增加的计算开销会给直接用于 RL 带来摩擦**，列为未来工作。
- **安全/隐私**：论文未涉及（无沙箱、无权限模型、数据都是公开数学数据集）。**这与我们的 fail-closed 姿态无关，不要从这里借安全设计。**

## 11. 评估方法

- **主指标 BoN@5**：从 5 条采样里选出分数最高的一条，看是否答对；同时报 **Pass@5** 作为**所有 Best-of-N 策略的性能上界**。这个设计对我们是重要的方法学提醒：**选择器的好坏必须与"候选池的上界"一起看**——Safe 在 Llama 3.1/MATH 上 60.0 对 70.8 的上界，说明**选择器仍有约 10.8 个点的空间没吃到**。
- **消融**：
  1. **分数融合方式**（Table 4，见 §8.4）；
  2. **与 ORM/PRM 的各种组合**（Table 3）：`ORM ⊕ PRM` 的组合确实也受益，但**提升不如 Safe**，Safe 在全部比较中稳定最优。
- **LLM-as-a-judge 的双重使用（且带一个负面发现）**：
  - 用来判**语义对齐**（good/fair/poor）与**学科分类**；
  - 但在**反馈质量**评估上，论文用 gpt-4 当裁判时**baseline 几乎在每个轴上都压过 LeanTutor**（这是 LeanTutor 论文的发现，此处不重复）；Safe 自己的用法是把 judge 用于**形式化陈述与步骤的对齐**，并明确**主要依赖人工观察来校对**。
- **我们可借用的被动信号**：
  1. **"形式化失败"与"证明失败"分开计数**——两个分母不同的比率（形式化率、证明率）本身就是笔记库的健康度指标，且**不需要模型**：只要我们的审查流程能记下"这条我们表达不了"与"这条表达出来了但判不了"。
  2. **每步 2 bit 的状态序列**——最省信息量的审查记录形式：**每条断言一个枚举值 + 一个原因**，而不是一段评语。这与我们的 frontmatter 白名单机制天然吻合。
  3. **错误样本比例失衡会毁掉判定器**——反向指标：如果体检发现"被标错的卡极少"，不要高兴，**先确认判定器是不是根本没在判**（论文里 GSM8K 上 LSTM 学不到错误模式就是这么发生的）。

## 12. 可迁移机制清单

1. **把"验证"变成"生成一条只判该步的陈述"**：前提 = 该步之前的内容，证明目标 = 该步的结论。这是"**claim 是否值得形式化**"这个问题的可直接操作化形式：**任何一步都可以被重写成"给定前文，结论必须成立"的条件断言**。
2. **"一切数值运算一律审"**——一条零判断成本的强启发式。不论多简单直观，数值运算都是幻觉高发区；对我们这样的笔记库，**含具体数字/代入计算的断言应一律进审查队列**。
3. **"跳跃/不直观"是审查判据**：有跳跃、可能含幻觉的步骤才需要形式化；**简单直观且无需验证的步骤显式标记为"不需要验证"**，而不是悄悄跳过。
4. **失败必须分类，不能合并**：`failed formalization`（表达不了/工具不够）≠ `proof failed`（陈述有问题）。这是"无法验证时降级为 unverified"的**机制基础**：两种降级原因必须分开。
5. **判定结果是枚举不是分数**：4 态、每态 2 bit。我们的 frontmatter 白名单同构，可直接把状态词作为可写值集。
6. **首选方案 + 确定性回退**：LLM 分解（质量高、可能输出不可解析）→ 解析失败就退回启发式规则（简单、确定）。**"优先走贵但好的路，失败时走便宜但确定的路"**是一个可复制的小模式。
7. **首要提示词的禁令清单**：只输出定理；不输出证明方法（用 `sorry`）；不用自然语言描述性质；不预测下一步。**对"审查"这个动作，禁令比指南更有效**（Danus 的摘要技能也是禁令式——两篇独立指向同一形态）。
8. **明确写出"表达边界"**：Lean 4 能处理数论/代数，几何/组合受限。**任何审查机制都应显式声明自己的能力边界**，边界之外的降级是正常输出而非失败。
9. **聚合而非逐态硬判**：单步判定有噪声（形式化可能错、ATP 可能预算不足），所以**不要用"某一步判失败"直接否定整条链**。对我们的含义：**一条卡上某句被判可疑，不等于整卡作废**；反之亦然。
10. **强否定信号下分数必须崩**：乘法融合优于求和/最大/最小。对应我们的排序：**`unverified` 或 `needs_review` 应当把卡压下去，而不是与好卡平均**。
11. **选对语料的成本结构**：同一个方法在强模型上应该把钱花在"验证每个样本"，在弱模型上花在"多采样"。对我们：**笔记质量已经不错时，把精力放在审查已有条目上比多写条目更值**。
12. **代价要如实写**：4–8 倍查询量、需要 3 次形式化 + 16 次证明的预算上限。**任何审查机制的建议都必须带成本数字**，这是本仓库 §14 要求的形态。

## 13. 与 dsh-math-memory 的映射与差距

现状（读代码确认）：`hook.verified` 白名单三值、模型只能写 `single-source`、`verified_by` 是凭据、体检有 `unverified` 一节（`verified ∈ {null, single-source}` 且 > 60 天）；`AUDIT_BODY_MAX_LINES = 20`、`AUDIT_UNUSED_DAYS = 30`、`AUDIT_WEAK_RATE = 0.4`、`AUDIT_STRONG_RATE = 0.8`、`AUDIT_DUP_JACCARD = 0.7`。

| # | SAFE 机制 | 我们现状 | 判定 |
|---|---|---|---|
| 1 | 每步重写为"给定前文 → 结论"的条件断言 | 无 | **采纳（协议层）**：给"审查单元"一个确定写法 |
| 2 | 一切数值运算一律审 | 无 | **采纳（协议层，零 token）**：体检可用确定性正则先捞"含具体数值的句子" |
| 3 | "跳跃/不直观"才需形式化；简单步骤显式标"不需要" | 无 | **改造**：不是所有句子都值得审——把"不需要审"也变成显式记录，避免审查被稀释 |
| 4 | 形式化失败 ≠ 证明失败 | 只有一个 `unverified` 桶 | **采纳（重点）**：`unverified` 必须带原因码 |
| 5 | 四态枚举、每步 2 bit | 三值 `verified` 白名单 | **已同构**；可把"审查状态"另立一个字段而不污染 `verified` |
| 6 | 首选方案 + 确定性回退 | 我们整体零 token 优先，天然是"确定性优先" | **反向采纳**：我们的默认路径就是它的回退路径；**贵路径（模型审查）应显式标为可选增强** |
| 7 | 禁令式提示（只输出 X） | 已有"不要手改统计字段"这类禁令 | **采纳**：审查协议的写法应继续用禁令 |
| 8 | 显式声明表达边界 | 我们面对的是自然语言笔记，边界更宽但更模糊 | **采纳**：`out-of-scope` 应是一等降级原因 |
| 9 | 聚合而非逐态硬判 | 体检是按卡逐条判 | **改造**：单句可疑 → 建议复读，不自动降整卡 |
| 10 | 强否定信号必须压分 | `verified` 权重 0.5/0.75/1 是线性加权，`needs_review` 未进排序惩罚 | **改造**：让 `needs_review`/`unverified` 显著压制排序 |
| 11 | 强模型上"验证已有样本"更值 | 我们笔记量小、质量不均 | **采纳（方针）**：优先审查存量 |
| 12 | 成本如实（4–8× 查询） | 我们的目标是不烧 token | **不适用其量级，适用其纪律**：任何审查建议必须标 token 成本 |
| — | Lean 4 / Lean REPL / COPPL / DeepSeek-Prover / MCTS / LSTM / PRM 集成 | 无任何形式化或训练依赖 | **不适用** |
| — | 形式化陈述本身（`theorem … := by sorry`） | 笔记是自然语言数学 | **不适用**：我们借的是**"条件断言"这个形状**，不是 Lean 语法 |

**差距的本质**：SAFE 解决的是"**LLM 生成的推理链**里哪一步错了"，它有 ground truth（最终答案）来训练选择器。我们解决的是"**人手写（或人问 AI 得到）的笔记**里哪条断言错了"，**没有 ground truth、没有标注、也不该训模型**。所以 SAFE 对我们可用的部分是**它的状态分类学与提示词判据**，不可用的是**它的聚合器与形式化栈**。

## 14. 行动项

> **[零 token]** = 确定性插件逻辑；**[需模型]** = 需模型参与（会话内，非插件调用）；**[做不到]** = 本仓库架构下不可行。

1. **[零 token] 给 `unverified` 加原因码，禁止无因降级。** 建议枚举 `no-source` / `out-of-scope` / `tool-missing` / `ambiguous` 四值（对齐 SAFE 的四态，其中 `failed formalization` 对应 `out-of-scope`，`proof failed` 对应真正的"这条错了"）。体检见到 `unverified` 无原因码就列为结构性缺陷。
2. **[零 token] 数值断言优先入队。** 用确定性规则（含阿拉伯数字、含 `=`/`≤`/`≈`、含单位换算、含百分比）把卡片正文里的**数值句**标出来，体检清单里单列一节"**待数值核对**"。依据是 SAFE 的"一切数值运算一律审，不论多简单"。
3. **[零 token] 把"不需要审"也记下来。** 对纯定义复述、纯引用、纯分类陈述，允许显式标注"免审"，理由必须是一句可核对的类型说明（如"这是定义复述，来源 <卡名>"）。**目的是让"未审"的量可见**，而不是让审查被无意义的句子稀释——直接对应 SAFE 的 `no verification required` 状态。
4. **[需模型] 审查单元的确定写法：`给定 <前提>，<结论> 必须成立`。** 写进 vault 协议：模型在做 Refine 步或体检跟进时，**必须先把待审的句子改写成这种条件断言**，再判断是否可核。这一步是"claim 是否值得形式化"的判据落地（问题 1 的答案）。
5. **[需模型] 噪声意识写进协议。** 协议要明说两件事：**"我判不了这条"不等于"这条错了"**；**"这条被判可疑"也不等于"整张卡作废"**。对应 SAFE 的两个假失败来源（形式化可能错、证明预算可能不够）。
6. **[零 token] 强否定信号压分。** 把 `needs_review: true`（或 `unverified`）纳入 `note_recall` 的排序惩罚，而不是只在展示时给徽标。依据是 SAFE 的乘法融合优于加权和这一消融结论。
7. **[零 token] 反指标告警。** 体检若发现"库里被判可疑的卡长期为 0"，应给一条**提示**而不是"全绿"：可能是**审查根本没在生效**（SAFE 里 GSM8K 上 LSTM 学不到错误模式就是这种情形）。
8. **[做不到] 用 Lean/ATP 做真正的机器验证。** 我们既没有形式化语料（SAFE 自己也只把 72.2% 的步骤形式化成功），也没有 Lean 环境与 prover 预算；且插件不调模型、不联网。**这条明确不做。**
9. **[做不到] 训练一个聚合器。** 无标注、无训练依赖、单用户规模不足。**保留其思想（聚合而非逐态硬判），放弃其实现。**
