## 1. 一句话定位

把「agent 的长期记忆」从**被动上下文**升格为**可调用的技能**：用 L1 可审计步骤证据 → L2 跨 episode 归纳的程序性策略 → L3 声明式环境认知的三层受治理记忆，只把「有证据支撑 + 增益为正 + 近期稳定」的 L2 策略**结晶**成带触发条件、适用边界、验证规则、证据锚点与可靠性估计的可调用技能；并用「反思加权价值回填」把稀疏的终点反馈沿稠密的自反思摊到每一步，从而同时治理记忆与技能的演进。

## 2. 问题与动机

要解决两个**同时存在**的失败模式：

1. **记忆是死的**：现有系统（factual memory 与 experiential memory 两派）检索出的历史轨迹只当被动上下文——插件安装轨迹里已经明明白白含「看 manifest → 解依赖 → 注册 → reload → 验可用」，系统仍把轨迹丢回去让模型**重新推理一遍**；反复探索过的仓库，agent 还会**再列一次目录**找测试/配置/构建脚本，纯烧 token。
2. **直接蒸馏技能是脆的**：原始轨迹里混着失败尝试、盲目探索、环境特有产物；终点反馈稀疏且延迟 ⇒ **步级信用分配不确定**；而且一个可复用技能不只要「成功步骤」，还要**触发条件、适用边界、验证判据、生命周期维护**——直接从轨迹蒸馏会过拟合、会在不合适的场合被调用。

一句话：**不加治理地从带噪轨迹蒸馏技能 ⇒ 又脆又专；只检索不结晶 ⇒ 记忆永远是被动上下文。**

## 3. 记忆结构

三层 + 一个下游技能库，`M = (M⁽¹⁾, M⁽²⁾, M⁽³⁾)`，技能库 `K` 在层级**下游**。分开的目的是「不让轨迹、策略、环境事实、可调用动作混成一个不受控的池子」。

| 层 | 形式 | 内容 |
|---|---|---|
| **L1 trace**（证据层） | `f⁽¹⁾ = (s, a, o, ρ, V)` | 语义状态 / 原子动作 / 环境观测 / **自反思 ρ** / **步骤价值 V**（初值 PENDING，终点反馈到达后回填）。**高层记忆与技能必须保留指向支撑 L1 的 id 链接** |
| **L2 policy**（程序层） | `f⁽²⁾ = (φ, π, κ, B, {f⁽¹⁾})` | 触发条件 φ / 自然语言过程 π / 验证或回退判据 κ / **适用边界 B** / 支撑证据集合。是「内部抽象」，可能不完整、不稳定、**不直接暴露给 agent** |
| **L3 env cognition**（声明层） | `f⁽³⁾ = (E, I, C, {f⁽²⁾})` | 实体/结构事实 E、动作–响应规律 I、环境约束 C，各自链到支撑的 L2。描述「**环境是怎么组织的**」，**禁止祈使句** |
| **Skill**（部署层） | `k = (φ, π, κ, B, A, D, η)` | 从合格 L2 继承 φ/π/κ/B，**新增** 证据锚点 A、决策指导 D、可靠性 η。有标准调用接口 + 生命周期状态 |

- **L1 有界**：不持久化无界原始观测，只存**归一化证据**（截断状态文本、动作文本、结构化工具调用元数据、带上限的工具输入输出），高层记忆只存**证据 id**。目的是同时压存储与降隐私风险。
- **L2 / Skill 的区别是刻意的**：L2 是「为了聚合证据与修订」的内部物；Skill 是「有生命周期、可靠性、证据锚点、决策指导的部署物」。**结晶不是格式化，是一次晋级。**

## 4. 写路径（固化）

**触发器：episode 结束 → 终点反馈到达 → 回填 → 下游链式更新**（Algorithm 2，各阶段按 episode id 幂等）：

1. **episode 定界**（Appendix B.2）：新用户消息由**轻量关系分类器**（词法线索 + 必要时 LLM tie-breaker）判为三类之一——`Correction`（纠正/否决上一结果 ⇒ **延长**上一个 episode，让新证据修订同一个信用分配单元）/ `Follow-up`（同一目标或环境延伸 ⇒ 关闭旧 episode、在同一任务上下文开新 episode）/ `New task`（无关新目标 ⇒ 开新任务上下文，长期记忆仍可检索）。**明确拒绝「把每次工具调用当独立任务」**——信用分配会过细、不稳。
2. **L1 落盘**：截断 + 抽取/合成 ρ + 打分 α + 嵌入摘要，写 `V = PENDING`。
3. **价值回填**（§4.4，Eq. 2）：终点步 `V(f_{i,H}) = R_i`；更早的步
   `V(f_{i,t}) = α_{i,t}·R_i + (1 − α_{i,t})·γ·V(f_{i,t+1})`，`γ = 0.9`，`α ∈ [0,1]` 由反思打分算子 Π_reflexion_score 给出。
   语义：**高 α 的步**是「对最终结果有本地信息量」的证据；**低 α 的步**主要从后续步继承价值。效果是**把记忆构建偏向「既被全局奖励、又本地可解释」的步**。空/同义反复的反思 α = 0。
4. **L2 关联或入池**（§4.2, B.5）：只有 `V ≥ v_min = 0.1` 的 L1 才进入关联或候选池。关联分 = **语义相似度 + 结构化触发重叠**；**领域 tag 不兼容或错误签名冲突时，即使嵌入相似度很高也拒绝关联**。不匹配 ⇒ 进候选池，按**确定性模式签名**分桶。
5. **L2 归纳**：同一签名桶积累**至少 n_min = 2 个不同 episode** 的证据才触发归纳。**独立性要求是「跨 episode 支撑」**——防止一条长轨迹自己撑出一个过专的策略。
6. **L2 修订**：新证据与活跃策略矛盾时**不直接覆写过程**：先重算增益；**持续负增益 ⇒ 退休**；**过程漂移显著 ⇒ 重新归纳并可能重建技能**。
7. **L3 抽象**（Algorithm 1）：按确定性领域键分桶，用**质心余弦相似度**做队列准入（θ_sim = 0.62，嵌入发散时回退 tag 对齐），队列规模 `m ≥ 2` 才调 Π_env；抽取**声明式**知识并**排除祈使式过程指令**；新草案与已有认知重叠（cos ≥ θ_merge）则**合并**，否则新建。**L3 的置信度 c**：新归纳的策略支持其既有事实则升、后续证据矛盾则降；**低置信认知不删除**（它们是有价值的历史/反面证据），只是**被排除出默认检索**直到出现新支撑。
8. **技能结晶**（§4.3）：两道门——① `G(f⁽²⁾) > θ_G = 0`（增益为正）且保留支撑证据；② **稳定**：近期证据应吻合当前 φ/π/B，而不是迫使大改写。满足后由 Π_skill 生成草案，构造支持集（**正证据 + 反证据**：正证据归纳公共过程，**反证据约束边界并产出反模式**）。
9. **确定性验证后才插入**（§4.3）：校验必需 schema（技能名、前置条件、有序步骤、示例、工具列表、决策指导字段）→ 强制**证据接地**：引用的证据 id 必须来自支持集、声明的工具必须来自**证据轨迹里实际出现过的工具白名单** → 两个轻量**覆盖测试**：草案既不能发明无支撑的命令，也不能偏离保留的轨迹证据。**任一检查不过 ⇒ 丢弃，不作为可调用技能暴露。**

## 5. 读路径（检索）

**三层级联，逐层降级**（§4.3, B.9）：

1. **技能优先**：路由器先用当前上下文匹配**活跃**技能的触发条件；命中后按 `触发相关度 + 可靠性 η + 源策略增益 G` 排序，取 `k = 3` 个。命中的技能把过程、前置条件、验证规则、边界、证据锚点、决策指导一起注入上下文。
2. **L3 只做先验，不写动作**：上下文同时命中 L3 认知时，L3 事实提供环境先验——**实例化参数、解释适用边界**，但**不覆盖技能过程**。例：依赖安装技能按 L3 认知里「这是 Alpine / Debian / macOS」来选包管理器命令。
3. **无技能命中或技能失败 ⇒ 回退 L1**：轨迹检索把**精确线索（如错误签名）**与**紧凑状态摘要上的语义相似度**结合；高价值轨迹优先，**低价值轨迹仍保留**（它们是反证据与决策修复的来源）。
4. **结构性不确定时取 L3**：agent 表达「不知道文件/测试/配置/约束在哪」这类结构不确定 ⇒ 检索相应 L3 认知。

**关键语义**：**技能不能自己单独生效**，它的调用**以记忆层级为条件**（conditions their invocation on the memory hierarchy）。这是「技能是缓存，层级是事实源」的分层。

## 6. 组织与关系

- **按「证据 / 过程 / 环境」三分而不是按「时间 / 主题」分**——这是全文最核心的组织判断。每一层有**明确的禁写清单**，靠 prompt 强隔离：
  - L2 禁写「环境拓扑事实」「纯声明式的环境行为规则」「脱离具体动作选择的环境禁忌」；
  - L3 禁写「祈使/建议动词」（do/don't/should/use/prefer/avoid/try/install/run），**环境认知永远不告诉 agent 该做什么**。
  - 论文明确说：「**两侧互相污染会同时稀释两边**」，并要求「同一个事实，两种表述」——「Alpine 不预装系统开发库」这个真值，在 L2 写成 `当 Alpine 容器内 pip install 因缺系统库失败时，apk add <pkg>-dev 后重试`，在 L3 写成 `Alpine 镜像只提供 Python 依赖栈的纯 Python 层`。
- **继承链而非图**：L1 ← L2 ← L3 ← Skill 单向指向上游证据（`{f⁽¹⁾}` / `{f⁽²⁾}` / A）。没有 L1↔L1 的语义边、没有图谱。
- **候选池 = 待归纳的组织单元**：按确定性模式签名分桶，跨 episode 计数到阈值才「诞生」一条 L2。

## 7. 维护与自改进

- **增益 G 是全会话的治理信号**（Eq. 1 + B.4），同时决定「策略留在活跃 / 够格结晶 / 该退休」：
  `G(f⁽²⁾) = V̄_with − V̄_blend(S_without)`；
  - `|S_with| ≥ 3` 时 with 侧用 **softmax 加权均值**（`τ_V = 0.5`），否则退化为算术均值；
  - without 侧用算术均值，并**向保守基线 `b = 0.5` 收缩**，伪计数 `N_0 = 5`：`V̄_blend = (|S_without|·μ + N_0·b)/(|S_without| + N_0)`。没有 without 证据时 `V̄_blend = b`。
  - 作者**明确声明这是启发式效用信号、不是因果效应估计**（Limitations 第一条也重申）。
- **技能生命周期**（Table 4）：`probationary → active → archived`。
  - `n_prob = 1`：至少被调用 1 次才开始评估；`η > θ_η^active = 0.6` ⇒ 进活跃检索；`η < θ_η^archive = 0.2`（或反复失败、用户明确否决、源策略负增益）⇒ 归档、不再默认检索。
  - **可靠性 η = (n_pass + 1)/(n_trial + 2)**（平滑成功率，拉普拉斯式）。显式反馈按步长 `δ = 0.1` 调整 η。
  - 事件–操作表：成功调用 → `reinforce`（升 η）；执行失败 → `repair`（改进程或验证）；**用户否决 → `shrink`（收窄适用边界 B）**；新反证据 → `revise`（加指导或反模式）；**源策略被重写 → `rebuild`（从证据重新结晶，而不是就地打补丁）**；长期不用或低可靠 → `archive`。
- **决策指导与修复 D**（§B.10）：当**两个动作模式出现在相似上下文但价值显著不同**、且低价值模式有失败或用户纠正支撑时，生成一条
  `d = (c, a⁺, a⁻, e, ξ)`（上下文 / 该做的 / 该避免的 / 证据链接 / 指导可靠性）。**只在上下文匹配当前技能或策略触发时才注入**；后续反馈可升、可降、可退休 ξ。工具失败爆发或用户明确纠正 ⇒ 合成对比式指导追加进 D，并把**修复包暂存到下一轮**注入，**而不是打断当前动作**。
- **交叉验证过的对照实验**：去掉整个层级（Flat Memory）掉分最多；去掉技能结晶在任何领域都掉分且成本全升；去掉价值校准（直接注入检索到的技能、不做适用性过滤）**每个领域都掉分且成本升** ⇒ 作者结论是「**避免有害的技能注入**需要适用性感知过滤」。

## 8. 验证与质量门控

多层、且**几乎全部是确定性的**（LLM 只在生成阶段，判定阶段是规则）：

| 门 | 时机 | 判据 | 失败后果 |
|---|---|---|---|
| 价值门 | L1 关联/入池 | `V ≥ v_min = 0.1` | 不进候选 |
| 独立性门 | L2 归纳 | 同签名桶 ≥ `n_min = 2` 个**不同 episode** | 不归纳 |
| 增益门 | 技能结晶 | `G > θ_G = 0` | 不结晶 |
| 稳定性门 | 技能结晶 | 近期证据吻合当前 φ/π/B（不需大改写） | 不结晶 |
| schema 门 | 插入前 | 名称/前置/步骤/示例/工具/决策指导字段齐全 | **丢弃草案** |
| 证据接地门 | 插入前 | 引用证据 id ∈ 支持集；声明工具 ∈ 证据轨迹工具白名单 | **丢弃草案** |
| 覆盖测试 | 插入前 | 不发明无支撑命令；不偏离保留的轨迹证据 | **丢弃草案** |
| 可靠性门 | 部署后 | `η > 0.6` 才进活跃检索；`< 0.2` 归档 | 降级/归档 |
| 越权检测 | 每日体检（对照） | 我们的 `verified` 等级高于 `single-source` 却缺 `verified_by` 凭据 ⇒ 列为越权升级 | 要求重判 |

**「谁有权改」**：LLM 只**起草**（反思打分、奖励量化、L2 归纳、L3 抽象、技能起草五个算子）；**判定权在确定性验证器**（schema + 接地 + 覆盖 + 阈值）。作者自己的 Limitations 承认：这些算子「虽然输出受证据约束并在插入前验证，仍可能带噪、对模型与 prompt 敏感，并引入额外延迟与成本」。

## 9. 成本 / 安全 / 隐私

- **成本论据（对「不做离线总结」有用）**：MSCE 的成本数字显示增益**不是靠多花推理预算换来的**——与各领域最强非 MSCE 基线比，IR/Math/Code/KW 的成本都下降（Math 与 Code 降幅尤其大）；唯一例外是 SE（Pass@1 +15.39 但成本 37.3 → 40.8 turns，作者归因于成功的软件工程解法本来就要更多仓库导航与测试）。
- **长期演进曲线**：「learning by using」——p0 → p100 累积经验下 Pass@1 单调上升（Math +17.00 / SE +15.39 / IR +13.84）；归一化成本在 p25 先升、随后持续下降，**p100 时 Math 与 SE 的成本低于 p0**。
- **隐私/有界持久化**（§B.11）：长字段截断、相邻重复步去重、规则式脱敏（敏感串移除）后才落盘；高层只存证据 id 而不是原始无界观测。作者明确说这些控制**不能消除**保留敏感信息、环境密钥或不安全程序性知识的可能，实部署需要更强的隐私过滤、访问控制与生成技能的安全检查。
- 技能数上限：每技能最多 `K = 6` 条证据轨迹；每任务检索 `k = 3` 个技能；验证器用 GPT-4o 做辅助算子、主干 GPT-5.2（成本与基线同构）。

## 10. 关键数字 / 阈值

**回填与奖励**：`γ = 0.9`；奖励权重 `w_g = 0.45`（目标达成）、`w_p = 0.30`（过程质量）、`w_u = 0.25`（用户满意度），`R_i = clip(0.45g + 0.30p + 0.25u, −1, 1)`；LLM 评估不可用时回退**极性启发式**。

**L2 归纳与增益**：`n_min = 2`（不同 episode）、`v_min = 0.1`、`τ_V = 0.5`、`N_0 = 5`、`b = 0.5`、`θ_G = 0`。

**L3 抽象**：队列最小规模 `m = 2`、准入 `θ_sim = 0.62`、相关主题 Jaccard 边阈值 `θ_edge = 0.34`。

**技能**：每技能证据上限 `K = 6`、每任务检索 `k = 3`、试运行最少调用 `n_prob = 1`、活跃阈值 `θ_η^active = 0.6`、归档阈值 `θ_η^archive = 0.2`、显式反馈步长 `δ = 0.1`。

**结果**（EvoAgentBench，Pass@1，最强非 MSCE 基线 → MSCE）：IR 21.54 → **26.15**（+4.61）、Math 43.00 → **47.00**（+4.00）、SE 38.46 → **53.85**（+15.39）、Code 61.54 → **61.54**（并列，成本 3.9 → 2.0 turns）、KW 48.28 → **53.45**（+5.17）。LoCoMo：综合 judge 61.23（次好 59.22）、F1 49.89（次好 48.71）。

**消融**（Pass@1 相对 Full MSCE 的下降）：Flat Memory 在 IR/Math/SE 上 **−15.38 / −16.00 / −19.23**，且 Code 成本 2.0 → 5.3 turns；w/o Skill Crystallization **−6.15 ~ −11.54** 且**每个**领域成本都升；w/o L3、w/o Value Calibration、w/o Reflection Weighting 均一致掉分；**w/o Value Calibration 在每个领域都掉分且成本升**。

**跨域迁移**：6 个迁移对全部提升，+2.56 ~ +5.13，平均 **+3.93**，4/6 成本下降。

**模拟人类反馈**（Table 7，C0 → C1）：KW +13.79、SE +7.69、Code +2.56、IR +1.54、**Math +0.00**（作者解读：数学瓶颈更在**符号正确性**而不在程序性改进）。成本趋势混杂（Code/IR/SE 降，KW/Math 升）。

## 11. 评估方法

- **主基准**：EvoAgentBench（自演化长程 agent，五域：IR=BrowseComp-Plus、Math=OmniMath、SE=SWE-Bench、Code=LiveCodeBench、KW=GDPVal），指标 Pass@1（宏平均）+ **Cost**（Math 用字符数，其余用交互轮数）。**成本必须与 Pass@1 合看**——作者自己声明低成本可能来自「提前终止或工具使用不足」。
- **副基准**：LoCoMo（考的是**记忆一致性**而不是工具技能执行，故单独汇报）。
- **在线协议**：所有在线方法的记忆与技能**只从在线演化 episode 累积**，不更新基座 LLM，之后再在后续评估里复用 ⇒ 这才是「自演化」的可信测法。
- **被动/稀疏信号的利用**：把**文本用户反馈**量化成标量奖励（三轴加权），并用 LLM 模拟人类反馈做受控研究（C0/C1）；论文自己也做了「反馈只在演化期注入、评估期不生成」的隔离。
- **我们能借鉴的**：① **cost 与 pass 必须同报**（我们 `engine-probe.mjs` 已经只报命中，没有代价视角）；② **在线累积 → 后评估**的协议（我们完全没测过「记忆长期积累是否让后续会话更好」）；③ **消融式的「去掉某层会掉多少」**（我们五层结构从未被这样验证过）；④ **净收益的符号**（呼应 GraphMemix §12 的「带符号净回收」）。
- 也可借鉴其**诚实**：Math 域模拟反馈零增益、SE 成本反升，论文照实写。

## 12. 可迁移机制清单

逐条能搬进 dsh-math-memory 的机制（按可落地性排序）：

1. **★ 「增益」作为卡片/策略的治理信号（而非只有 uses/success_rate）**。我们的 `hook` 现在有 `uses / success_rate / last_used / harmed / verified`，但**没有「用了它比不用它好多少」**。MSCE 的 `G = V̄_with − V̄_blend(without)` 且**without 侧向保守基线收缩**（`N_0 = 5, b = 0.5`）正是「小样本不要妄下结论」的确定性写法，可直接抄袭其**形状**（用我们的确定性代理量替换 V）。
2. **★ 适用性感知过滤是硬要求，不是可选优化**。MSCE 的「w/o Value Calibration **每个领域**都掉分且成本升」= 「**盲目注入技能是有害的**」的实证。对应到我们：`not_applicable_when` 硬门控 + `verified` 权重**不能**被当成锦上添花，必须视为防害机制；且**值得为它补一条断言**（见 §14 A2）。
3. **★ 「边界」是一等公民且会被「收窄」**。我们不缺 `not_applicable_when`，缺的是它作为**生命周期对象**被反馈修改：MSCE 里「用户否决 ⇒ shrink boundary」，我们的 ❌ 目前只改 `success_rate` + `verified` 降级。**收窄边界是可加的确定性动作**（把被否决的上下文特征追加进 `not_applicable_when`）。
4. **★ 反证据与反模式的显式结构**。MSCE 用「正证据归纳过程、**反证据约束边界并产出反模式**」，且决策指导是 `(上下文, 该做, 该避免, 证据, 可靠性)` 的**对比对**。我们有 `harmed` 计数与体检里的「反模式」，但反模式**没有结构、也没链到具体策略卡**。可低成本升级为策略卡的 `prefer[] / avoid[]` 对比对（各带 evidence）。
5. **★ 技能结晶的「两门 + 三验」形状**。我们 `strategy/` 已有 `status: candidate → active`，promote 条件 `uses ≥ 3 且 success_rate ≥ 0.6`——这其实就是 MSCE 的可靠性门（且阈值 0.6 巧合一致）。缺的是：① **增益门**（有没有比不用更好）；② **稳定性门**（近期证据是否吻合当前 move/retrieve，而非需要大改写）；③ **接地校验**（策略卡声称的定理/技巧是否真在支撑证据里出现过、`provenance` 是否完整）。③ 是纯确定性的，最该先做。
6. **★ 证据锚点是技能可被信任的前提**。MSCE 反复强调「高层记忆存**证据 id** 而非复制原始观测」，且技能的 A 是晋级门槛。我们的策略卡有 `provenance`，但 `records` 的 `source` 只指向 episode——**策略卡应显式列出其支撑 records/techniques 的 id 列表**，这样「这张策略凭什么可信」可一键回溯。
7. **★ 稀疏终点反馈沿链回填（用确定性 α 代理）**。这是 MSCE 最独特的一件，且**与我们的红线不冲突**——只要 α 是**确定性**算出来的。我们实际上已经有一个天然的「反思」载体：`episodes` 原文 + `records` + 体检报告，而 ❌/✅ 是很稀疏的终点反馈。可以设计：**episode 收尾时按确定性规则给本回合的每条写入分配一个 α 代理**（例如「用户随后是否继续追问同一问题」「本轮结论是否在后续被 supersede」「是否触发了 ❌」），再沿「step → episode → record」把终点反馈回填成一个 `gain` 增量。**这一条是「技巧调用体系」缺失闭环的真正缺口。**
8. **「跨 episode 独立支撑」作为去重/晋升的前提**。MSCE 拒绝让一条长轨迹自撑出一个策略（`n_min` 个**不同** episode）。我们的体检报「疑似重复」，但**没有「同一模式被几个独立 episode 支撑」这个计数**——这恰好是区分「一次巧合」与「真技巧」的确定性判据，且数据已经在 `episodes/` 里。
9. **分层检索的「先技能、后证据」与「回退」语义**。我们 AGENTS.md §5 已有粗到细路由，但**没有显式的「技能失败就回退 L1 轨迹」的降级链**。补一段协议文本成本极低。
10. **「技能注入必须被层级条件化」**：技能只给过程，参数与环境先验由上一层给（Alpine/Debian/macOS 例）。对应我们：**策略卡给「困难→策略→检索目标」的骨架，具体定理/记号由 vault 的 `notation`/`theorems`/`topics` 实例化**——这正好是我们已有的分层，值得把这个「谁实例化谁」的边界写清，避免策略卡越权写死具体结论。
11. **低置信对象「不删除、只排除出默认检索」**。我们有 `superseded`/`archived`/`needs_review` 三态，精神一致；MSCE 的补充是 L3 的**置信度可升可降且低置信仍留在盘上作历史证据**。可对齐到 `confidence` 字段（我们已有 `confidence: 0–1`）的**双向**使用：现在文档只说「被质疑时下调」，没说被支持时上调。
12. **决策修复「暂存到下一轮、不打断当前动作」**。我们的 model 是「回复末尾一行说明」，天然不打断；但**把修复包显式暂存**（如写进 `working.md`）使「下一轮一定看得到」是有价值的确定性加强。
