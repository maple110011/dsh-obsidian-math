## 1. 一句话定位

把「记忆投毒」系统化：长期记忆只有**四条写通道**（C1 显式指令执行 / C2 系统提示策略 / C3 压缩 / C4 经验→技能），而模型、提示词、架构三层共**九条结构脆弱性**让这四条通道可被利用；据此给出**六类攻击**分类法与 **MPBench**，在两个 agent 上实测出总体 **ASR 50.46% / RSR 41.05%**，并证明「更激进的写与检索 ⇒ 更易被利用」与「现有 prompt-injection 防御盖不住记忆投毒」（§1、Abstract、Table 2）。

## 2. 问题与动机

- 与 prompt injection / jailbreak 的本质差异：那些攻击的载荷**每次都必须出现在活跃上下文里**；记忆投毒**只需要一次成功写入**，此后该条目被当作可信先验知识反复取用（§1）。
- 根因：agent 记忆由**不可信外部内容**构造（网页、文档、邮件、工具输出），写完却"作为内部上下文被当作可信知识"，而**当前系统没有可靠机制追踪存储条目的来源**。原文：「Once written, however, this content is later retrieved as part of the agent's internal context and treated as trusted knowledge.」（§1）——中译：一旦写下，这些内容此后就会作为 agent 内部上下文的一部分被取回，并被当作可信知识。
- 现有工作缺口：要么威胁模型过强（要求直接访问记忆，如 Agent-Poison），要么只评估孤立攻击；**没有统一的脆弱性分析**，因此防御设计缺乏原则依据（§1）。
- 与既有基准的分界（§4.1）：记忆性能基准（LoCoMo / LongMemEval / MemBench）无对抗成分；agent 安全基准（AgentDojo / InjecAgent）是**单会话**评测（"载荷在本次交互内生效并在同一次交互内测效果"）。MPBench 是**第一个把评测拆成"写入段 + 检索段"两段**的记忆投毒基准。

## 3. 记忆结构

**（这是对我们最有价值的部分）**

- 形式化：记忆系统 `M = (S, W, R)`，S 为持久存储、W 为写函数、R 为检索函数；攻击 `P = (x_adv, C_i, t)`，**成功判据** = 处理含 `x_adv` 的输入后，`S'` 里出现目标指令 `t` **或其语义等价改写**（§2.1、§3）。
- 长期记忆三型（§2.1）：**事实记忆**（用户/环境的知识与偏好）、**经验记忆**（过去动作与结果）、**过程记忆**（可复用技能；**直接支配执行，因此是影响最大的写入目标**）。→ 我们只有"事实层（records/topics/profile）+ 事件层（episodes）"，**没有独立的、直接支配执行的程序层**。
- **四条写通道**，按「触发者」与「写入权限归属」两维区分（§2.2、Table 1）：

  | 通道 | 触发（trigger） | 写入权限（write authority） | 直写/推断 |
  |---|---|---|---|
  | C1 显式指令执行写 | 外来指令本身 | 该指令（模型不做额外推理） | **直写** |
  | C2 系统提示驱动的写 | 任意被处理内容（隐式） | 模型对"是否满足留存策略"的判断 | 推断 |
  | C3 压缩驱动的写 | 系统级阈值（上下文满 / 会话结束） | 压缩提示 + 模型摘要 | 推断 |
  | C4 经验→过程写 | 执行轨迹的结构信号（新手艺 / 纠错 / 用户纠正 / 成功完成） | 模型自己判断"这构成可复用流程" | 推断 |

  C1 与 C4 的区分不是"输入是什么"而是"什么发起了写"：用户明确要求"把这次经验总结成技能"算 **C1**（触发与权限都是用户指令）；C4 是 agent 从执行轨迹自身结构认出"我刚做的是一套可复用流程"（§2.2）。
- **三层九条脆弱性**（§2.3，映射见 Table 1）：
  - 模型层：**V-M1 指令-数据边界盲**（所有输入被展平成一个 token 序列，外部内容像指令就被当写命令执行）；**V-M2 多源上下文来源归属失败**（无法可靠判断内容来自哪个源，于是不可信内容与可信输入等价）。
  - 提示层：**V-P1 写入策略欠定义**（判据是"保存相关或重要信息"这类自然语言模糊标准，如 OpenClaw v2026.3.38，写入决策全交给模型解释）；**V-P2 压缩不筛来源**（压缩时按"感知重要性"统一处理，不区分可信/不可信）。
  - 架构层：**V-S1 写路径无校验**（决策与落盘之间没有验证步骤）；**V-S2 多源共享上下文**（用户输入、检索数据、工具输出、既有记忆同处一个上下文窗口，无隔离）；**V-S3 压缩触发可操纵**（触发条件是 token 阈值，攻击者可用载荷长度把它顶到）；**V-S4 技能创建无校验**（技能文件直接提交、无检查——结构上等同 C4 上的 V-S1，但目标影响更大）；**V-S5 自我改进即放大**（执行没报错就被当作已验证，后续修订都建在这个含毒基线上，毒技能越迭代越优化）。
- **V-S5 是全文唯一"静态记忆系统里没有对应物"的脆弱性**（§2.3.3）。

## 4. 写路径（固化）

- 论文不提供写入纪律，而是把**写入纪律的缺失本身**列为脆弱性：V-S1（决策到落盘无校验）、V-P1（判据只有模糊自然语言）、V-S4（技能直接提交、无审批）（§2.3）。
- C1 是唯一**直写**：写入内容由外来指令决定，模型不推理（§2.2）——即投毒载荷**不必通过模型的"该不该记"判断**。C2/C3/C4 都是推断写，是弱信号攻击的着力点（§3.2.1）。
- **六类攻击**（§3.2 + Appendix B，通道与信号强度见 Table 2）：
  1. **Explicit Command Insertion**（C1，强）——把写指令直接嵌进外部内容，靠可辨识的语言模式：祈使动词（remember/store/save）、显式记忆命令（add to memory）、用户偏好框定（the user prefers）、时间持续线索（always/from now on）（Table 5）。
  2. **Conditional Command Insertion**（C1，强）——载荷不发即时写命令，而是埋一条条件指令，等用户自然说出 yes/ok/sure 才落库。
  3. **Salience-Driven Compaction Poisoning**（C3，强）——把恶意内容**重复 ≥3 次**（词面重复或语义改写），压缩把"重复"当重要性信号，于是被写进持久记录（D.3 给了这个构造约束）。
  4. **Policy Conformant Fact Injection**（C2，弱）——**无任何指令痕迹**，伪装成 world fact（政策/流程/标准）或 user fact（偏好/要求），只为满足模糊留存策略。
  5. **False Precedent Insertion**（C2，弱）——伪造一条**符合经验记忆 schema** 的"过去成功记录"（任务描述 / 做法 / 结果），让 agent 把攻击者步骤当既有经验复用。
  6. **Skill-Procedure Insertion**（C4，弱）——构造能触发技能合成的任务轨迹，对抗步骤随执行轨迹被蒸馏进技能，再被自我改进循环强化、被下游步骤依赖。
- **强/弱信号二分是全文最有用的一个划分**（§3.2.1）：强信号在原始输入里**可被分类器还原**；弱信号**在输入层与合法内容不可区分**，被写进去"不是因为有写命令，而是因为它看起来像事实/政策/经验"。

## 5. 读路径（检索）

- 检索是攻击链的第三个目标：投毒条目必须在未来会话被检索到，并在攻击者不再介入的情况下影响推理或动作（§3.1）。
- **两个 agent 的 RSR 差距主要由检索形态决定，而不是写策略**（§4.4）：HERMES 在会话开始时把持久记忆作为**冻结快照注入系统提示**，毒条目无需显式检索就在上下文里；OpenClaw 只在 agent **主动调用记忆搜索工具**时取记忆。→ 这解释了 64.70% vs 17.40%。
- **对我们的直接含义**：我们的记忆卡是**每次组装系统提示就注入**（note-noise §1.1），在检索这一维上属 **HERMES 型（高 RSR 形态）**；而 `note_recall` 属 **OpenClaw 型（工具检索）**。我们是混合体，且注入那一半正落在论文的高风险档。
- 论文**没有**任何检索排序/打分/空结果语义的设计——它把检索当攻击面，不当工程对象。这是它与 MemTrapBench 那类"记忆使用阶段"工作的分工差异。

## 6. 组织与关系

- 论文的组织维度是**「脆弱性 ↔ 写通道 ↔ 攻击类」三元映射**（Table 1、Table 2 的 Vulnerabilities Exploited 列），而不是记忆内容的分类法/链接/图谱/层级导航。
- 唯一带"组织"意味的建议在 §5：**写路径来源追踪（provenance）**→ 支撑"来源感知的检索策略"，对不可信来源的条目**降权或隔离（quarantine）**。这是我们组织层最该看的一条，但**属作者推断、未做实验**。
- 换言之：它给的"从有什么到取什么"的机制 = **按来源而不是按内容质量组织**。

## 7. 维护与自改进

- **V-S5 是全文唯一直接谈"自改进"的机制，且它是负面的**：自我改进循环把"执行没报错"当成验证事件，于是毒技能不但不被清理，反而被优化、被下游步骤依赖（§2.3.3）。论文对它的**实测只有 Skill-Procedure Insertion 一类的 ASR/RSR（58.33 / 61.67），没有测跨迭代的动态演化**（§4.2、Table 2）。
- §5 第三条建议**写后监控（post-write memory monitoring）**：不要维护"已知攻击模式清单"，而应拿记忆候选去对"这个 agent 被授权存什么 / 被授权做什么 / 被允许连哪些端点"作判断——**随 agent 能力扩展而扩展，而不是随观察到的攻击面扩展**，因此能覆盖没被枚举过的新攻击类。
- 与我们体检机制的关系：我们的体检是确定性、只报不改、不是模式清单 —— 形状对上了；但判据是**库内一致性**（单源 60 天、疑似重复、卡级矛盾），**不是授权边界**（缺口见 §13）。

## 8. 验证与质量门控

- ASR 与 RSR 都用 LLM judge：ASR 判"某条记忆条目 e 与目标 t 是否编码同一行为指令"；RSR 判"后续回答 a 是否体现该指令"（§4.1.3，式 1/2）。
- 质检流程：每条用例由结构化模板锁死四输入（攻击类、信号强度、领域、对抗目标），用 Meta-Llama-3.1-70B-Instruct 合成可变部分（用户 query / 含载荷上下文 / 期望记忆条目 / 检索 query），逐条做 **schema 校验**并**跨类跨域抽检**（D.1）。
- judge 验证：**只写了"经随机样本人工标注确认与人类判断一致"，没有给一致率数字**（§4.1.3）。
- 论文**没有**：置信区间/显著性检验、按 7 个领域拆分的 ASR、每类实际评测分母。
- 我们能借鉴的：**ASR（写入侧命中率）与 RSR（检索侧影响率）是两个可以分开测量的量**——我们的体检今天只有注入长度、uses 这类代理量，既没有"写进去了没有"，也没有"取出来有没有改变行为"（§11 详述）。

## 9. 成本 / 安全 / 隐私

- 威胁模型是**黑盒**：攻击者不能读写记忆、不能改系统提示、不能冒充用户、看不到内部推理与中间状态；只能把载荷放进 agent 正常处理的外部内容（网页/文档/邮件/工具输出）（§3.1）。
- 明确排除（§3.1）：有特权访问的攻击者、多用户共享同一记忆库、知道底层模型的攻击者——"这些是更强的威胁模型，与本工作的脆弱性正交"。
- 攻击者代价极低（§1、§3.1）：一次成功写入即可长期生效；C1 只要求攻击者知道"agent 会响应自然语言指令"，C3 的载荷长度可从可观测的上下文上限推断。
- 数据侧：全合成，无真实用户数据；两个 agent 都用 **GPT-OSS-120B** 与默认系统提示、默认记忆配置（§4.1）。**没有报告 token / 费用开销**。
- 对我们要注意的一点：论文的对手是**有意图的攻击者**，而我们 note-noise 关心的主因是**无对手的噪声与 AI 补全**。两者共享"写进去 → 当成事实取用"的机制，但**威胁模型不同**，引用时不能互换（见 §15）。

## 10. 关键数字 / 阈值

**论文真实出现的：**

- OpenClaw 平均 **ASR 34.25% / RSR 17.40%**；HERMES 平均 **ASR 66.67% / RSR 64.70%**（Table 2）。

## 11. 评估方法

- MPBench 用例 = 四件套：任务场景（7 域）、对抗载荷（嵌在环境数据里）、写入检查、检索检查（§4.1.1）。
- 两种交付模式（§4.1.2）：**静态上下文**（载荷以"外部数据"标签直接给出）与**动态工具调用**（agent 须自己取文件）。论文声明这"纯粹是数据收集选择，不影响 agent 行为或评测"。
- 核心方法学贡献是**两段式度量**：ASR 测写入，**RSR 只在 ASR 为正的用例上**测跨会话影响（§4.1.3）。
- 实验矩阵：6 攻击类 × 2 agent × 强/弱信号 ×（4 个防御 × off-the-shelf/适配）。
- 我们能借鉴的：
  1. **「写进去了没有」与「取出来有没有改变行为」分开测** —— 我们的门禁只有"注入文本含某串"与"检索可达性"两类断言，**没有"注入内容是否改变了模型行为"这一层**。
  2. **良性样本专用于 FPR**（2,997 条）—— 对应我们 `noteClaims` / `unverified` 这类"喊狼来了"的风险，今天没有 FPR 度量。
  3. 用人工抽查给 judge 做验证锚——但论文只写了"确认一致"、没报数字；**我们若做就必须报数字**（不要学这一处）。

## 12. 可迁移机制清单

（逐条 = 能搬进 dsh-math-memory 的具体机制；`采纳` = 概念可照搬，`改造` = 要动我们的实现，`不适用` = 记录理由后不引）

1. **【采纳】四条写通道当作自审表**：逐个问"我们系统里这条通道存在吗、谁把关"。答案是——C1/C2 **存在且部分无校验**（模型可直接写 records/topics/profile，`structure` 档还是自动写）；C3 有**近似物**（会话日志→episodes→模型手写 records 的蒸馏 + 索引摘要的预算裁剪）；C4 **不存在**（无过程记忆层）。
2. **【采纳】强/弱信号二分进我们的威胁词汇**：我们今天的风险讨论默认"脏内容是模型自己编的"（=弱信号），完全没有"外部内容里带显式写指令"这一类（=强信号）。两类需要不同防线：强信号靠输入层不执行/标记，弱信号只能靠**写路径判据 + 来源**。
3. **【改造】写路径来源追踪（provenance）**：注入/检索时能说清"这条记忆来自用户、来自 AI 归纳、还是来自被处理的外部文档"，并据此降权或隔离（§5，作者建议、**未实测**）。直接对应 note-noise **缺口 3** 与 **P6**。
4. **【改造】来源隔离**：V-S2 的解法是"别让不可信外部内容在写入决策里与已认证用户输入等价"。我们已有半个 —— 会话捕获只取 `source.kind === "user"` 的真实用户消息（note-noise §2.3）。**缺的是"模型写 records 时，内容来自用户原话还是来自笔记/工具输出"这一维**。
5. **【改造】压缩过滤器（compaction filter）**：把上下文压成持久记忆时区分可信/不可信来源，别让对抗内容随良性信息一起进库（§5）。对应我们的 episode→records 蒸馏段 —— 今天**没有确定性蒸馏**，全靠模型手写（note-noise §2.3 表格末行）。
6. **【采纳】写后监控按"授权边界"而非"攻击模式清单"**：拿记忆候选去对"允许存什么/允许做什么/允许连哪些端点"（§5）。我们体检已有确定性、非模式清单的形状，可把判据从"库内一致性"扩到"授权边界"。
7. **【改造】V-S5 的镜像警惕**：把"检索命中"当验证信号，正是论文里"把执行无错当验证"的同构错误。我们的 `uses → hookPrior` 就是这条（note-noise **缺口 5**、P5-②）。
8. **【改造·有条件】载荷长度顶阈值（V-S3）的镜像**：外部内容规模能挤掉注入预算里的旧行。我们对应 `appendOnlyIndexDigest` 超预算**静默丢最旧行**（note-noise **缺口 8**）。但 note-noise §1.4 实测基准库注入 **4088 / 18000**，**这条今天不生效**——只在库变大顶到各层预算时才出现。
9. **【采纳】两段式指标（ASR/RSR）作为体检被动信号的雏形**：把"这类内容被写进去的概率"与"它被注入后是否改变了回答"分开度量，替代只看注入长度的代理量。

## 13. 与 dsh-math-memory 的映射与差距

- **采纳（概念可照搬）**：强/弱信号二分；四条写通道自审表；「写后监控按授权边界而不是模式清单」（我们体检的既有形状已兼容）；两段式指标的形状。
- **改造（要动我们的实现）**：
  - provenance 字段 + 来源感知的降权/隔离 → **缺口 3 + P6**（新字段必须有读取方，否则是坑 34 复发）。
  - **C2 通道的写策略收窄**：`capture-policy` 里 `structure` 默认 `auto`（note-noise §1.2）等于把写入权限交给模型判断 —— 这正是 **V-P1 的形态**，是全文对我们**最尖的一刀**，对齐 **D1 选项 A / P4 的 `stage: draft`**。
  - `uses → hookPrior` 不再把"被检索"当验证 → **缺口 5 / P5-②**（V-S5 给了这条改动一个外部类比：**"执行没报错"不是验证**）。
  - 体检清单加"未核实/无来源"项并前置 → **缺口 1、7 / P3 的既有落地形状**。
- **不适用（记录理由）**：
  - **C3「压缩」这条通道的强形态**：我们没有"上下文满→自动压缩落库"的机制（会话捕获是开关式的，默认 `false`），因此 V-P2 / V-S3 只在"索引预算裁剪"这个弱形态上成立。
  - **C4 / V-S4 / V-S5**：我们没有过程记忆、没有自主技能合成，不适用；引进来只会制造假风险。
  - 论文的威胁模型（黑盒外部、无特权）比我们关心的"无对抗噪声"更**窄也更专**——我们怕的是无对手的脏，它怕的是有对手的写。
- **我们与它的最大差距（三条）**：
  1. **可信度只在"库内一致性"维度上建立**（`single-source`/`cross-referenced`/`user-confirmed` 全是"这条内容自己可不可靠"），**没有"它从哪来"这一维**；而论文的整个攻击面恰恰是**来源维**。
  2. **注入是自动的**（每次组装系统提示都注入）⇒ 落在高 RSR 的 **HERMES 形态**；而我们对注入内容**没有"降权/隔离"的出口**（P6 缺），只有"归档"与"全停记忆"。
  3. **没有"待澄清/待定论"的中间态**（缺口 4）；而论文的弱信号攻击正好是"看起来完全正常"的那一类 —— 今天我们对"看起来正常的错东西"只有一个事后 `unverified` 计数。
- **证据强度提醒（引用时必须带上）**：论文**没有实测任何防御**（来源隔离、provenance、写后监控、压缩过滤四条都在 §5 讨论里，零数据）；「更激进的读写 ⇒ 更易被利用」是**两个 agent 的对比**（n=2、无消融），且 ASR 差由"策略宽松 + 压缩阈值 2200 字符"解释、RSR 差由"自动注入 vs 工具检索"解释，**都是结构性归因，不是受控实验**。

## 14. 行动项

（对我方的具体建议，供跨论文汇总；每条标 `采纳 / 改造 / 不适用` + 要动的环节 + 验收形态）

1. **【改造·最高优先】把 `capture-policy` 的 `structure: auto` 收窄**（至少加一条"内容来源不是用户原话时不得 auto"的规则）—— 这是 V-P1「写策略欠定义 + 写入权限归模型」在我们系统里的**唯一逐字对应物**（note-noise §1.2 的 capture-policy 表；对齐 **D1 选项 A** 与 **P4**）。验收：断言"非用户来源的 structure 候选在 auto 档下不落盘"，用**构造条件 + 否定性用例**，不锚在 fixture 上（AGENTS.md §6）。
2. **【改造】新增来源字段**（如 `origin: user | ai-inferred | external`）并让它在**注入行上可见** → 直接补 **缺口 3**；与 **P2**（可信度进注入）共用同一套逐行标记机制，复用 `hook-frontmatter.mjs`，别写第二份 frontmatter 正则（坑 65）。注意：新字段必须有读取方，否则是坑 34 的复发。
3. **【改造】把 `uses` 从 hookPrior 的"验证信号"降级为"曝光计数"** → **缺口 5 / P5-②**。须先过 `docs/memory/retrieval-v3.md` §7.5 的「Direct 数不降且排名均值不升」门槛，并跑 `scripts/qa/engine-probe.mjs`。
4. **【采纳】给"待澄清/待定论"一个出口** → **缺口 4 / P6**。论文没这个机制，但它证明了**弱信号内容在输入层与正常内容不可区分**，所以"看起来正常"不能作为"可以用"的理由；用户需要一个不撒谎的中间动作（✅ / ❌ / 过期 / 归档之外）。
5. **【改造】体检新增"无来源"发现**（有 `source` 但不指向任何 episode；或 `origin: external` 却出现在 records 层），与 `unverified` 一起前置 —— 沿用 P3 的落地形状与"夹具必须跨 1200 字符阈值"的纪律（坑 81）。
6. **【采纳】把 ASR/RSR 两段式做成被动信号雏形**：体检至少能回答"上一批被注入的记忆里，有多少条让回答变了" —— 今天完全测不到（§11.1）。

8. **【证据纪律】引用本条时必须同时说**：论文未实测任何防御；"激进读写 ⇒ 更易被利用"来自两个 agent 的对比而非消融；单模型 GPT-OSS-120B；弱信号检出率低是**输入层分类器**的度量，不是"记忆投毒不可防"的证明。
