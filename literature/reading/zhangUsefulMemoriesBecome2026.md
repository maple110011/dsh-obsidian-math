# 研读记录：zhangUsefulMemoriesBecome2026

## 0. 元信息

- citekey：zhangUsefulMemoriesBecome2026
- 标题：Useful Memories Become Faulty When Continuously Updated by LLMs
- 年份：2026（arXiv:2605.12978，UIUC + 清华 IIIS）
- 阅读日期：2026-10-01
- 阅读方式：MinerU 全文通读（`.raw/zhangUsefulMemoriesBecome2026/full.md`）；§4–§7 逐段读，附录（A–L）按需抽查
- 一句话立场：这是「AI 反复改写笔记 ⇒ 笔记越改越错」最直接的一篇**实测**证据，且它的补救方案不是"降低权重"，而是**分开两个存储 + 给固化加闸门**。

## 1. 一句话定位

在"输入轨迹本身有用"（甚至给的是**标准答案**）的条件下，让 LLM 持续把轨迹固化成文本记忆库，记忆效用会**先升后降、最终低于无记忆基线**（GPT-5.4 在自己 100% 解出的 19 题 ARC-AGI 切片上，经过流式固化后准确率掉到 ~52.6–54%）；损坏来自**固化步骤本身**（有损重写、就地改写、以旧抽象为上下文），而不是经验质量。补救：原始 episode 当一等证据，固化必须**显式设闸**，不能每轮自动触发。

## 2. 问题与动机

- 主流 agentic memory（CLIN / AWM / Dynamic Cheatsheet / ACE）都采「每轮交互后更新一次」的固化设计，隐含假设：每次固化**至多中性**。本文用受控实验否证这个假设。
- 相对灾难性遗忘：本文的退化**不是**任务分布变化引起的——任务集固定、同一批轨迹，"把整个池子一次性固化（Static-All）"明显好于"分批流式固化（Stream）"，Fig. 3 报 **Stream 相对整池一次固化掉 17–38 分**（§4.1）。
- 三个纠缠的失败模式（§6）：**误分组**（把不共享结构的 episode 池在一起再去抽象）、**过度泛化**（抽象剥掉适用前提）、**过拟合窄流**（对着见过的实例写规则）。

## 3. 记忆结构

- 显式的**双存储**（§3，ARC-AGI Stream，借 Complementary Learning Systems 框架）：
  - `Episodic buffer`：problem–solution 对的原始轨迹；
  - `Abstract store`：跨 episode 固化的 lesson。
- 每一步模型可选三个动作：`Retain`（留原始 episode）/ `Delete` / `Consolidate`（把 buffer 里的 episode 固化进 Abstract store）；解算器可只吃 episodic、只吃 abstract、或两者都吃。
- 三种控制回路：`Force`（每轮必须固化，且轮次之间不保留 episodic）/ `Auto`（模型自己选留原始还是抽象）/ `Episodic Management Only`（只允许保留与删除，**彻底禁用抽象**）。
- 对照我们的三层记忆：`episodes/**` 是 episodic store（原文落盘、只注入索引行），`records/topics` 是 abstract store。**差别在于我们没有一个"Auto"闸门**——三写协议本来就是"每轮都可以写"。

## 4. 写路径（固化）

- **效用随固化次数非单调**：ScienceWorld 上 batch=4 时峰值在 step 20 附近，之后一路下降到 step 100，且**有时低于无记忆基线**（Fig. 1a）；WebShop 上 AWM 从 8 例的 **0.64** 掉到 128 例的 **0.20**，而无记忆恰好是 **0.20**（Fig. 1b）——"把记忆做大"把收益自己抹平了（§4.1）。
- **好记忆不是不动点**：先用 GPT-5.4 做一次高质量 Static-Group 固化，再用 GPT-5-nano 继续在原轨迹池上增量更新，在三个不同解算器（Qwen3.5-27B/9B/4B）上效用**全部下降**，且相邻评估步之间可能暴跌（Fig. 4）。
- **哪种更新最伤**（Table 5，ARC-AGI Stream，GPT-5.4，batch=1，step 400，强制更新）：
  | 流式变体 | 去掉了什么 | 准确率 |
  |---|---|---|
  | 默认固化（就地改写） | — | **43.2** |
  | append-only，旧库可见（A） | 就地改写 | 50.0 |
  | 加/删，不做就地编辑（C） | 就地改写（保留剪枝） | 64.0 |
  | append-only，旧库**隐藏**（B） | 改写 + 旧抽象作为上下文 | **70.0** |
  | 原始轨迹（不固化） | 全部固化 | **76.6** |
  → 两个可迁移点：① **就地重写是单项最伤的动作**；② **剪枝（删而不改）反而有益**；③ 即使全部改掉，仍未追平原始轨迹（第一次抽象就已丢信息）。
- **分组与批次影响固化质量**：按任务族分开固化（Static-Group）优于跨族一起（Static-All，Fig. 3）；异构批次加速衰退（Fig. 4），因为模型会**合并互不相容的 lesson**（§4.1）。
- **规模/能力都救不了**：7 个已发表框架（LangMem/Mem0/ProPlay/ACE/AWM/Letta/Dynamic Cheatsheet）至少在一种设定下从峰值退化（§4.3，完整表在 §L.6）；把记忆管理交给前沿 coding agent（OpenCode，各模型最大推理预算、可自由检视/修订/删除）后，四个 backbone 仍然"先升后降"，GLM 5.2 回到无记忆水平、DeepSeek V4 Pro 掉到其下方（Table 3）。
- **不是上下文长度的问题**：把 prompt 填充到 ~790K tokens，准确率变化 < 4 分（§L.5）；prompt 优化（GEPA）只恢复部分损失，而且靠的是**教解算器不信任记忆**（§L.7）。

## 5. 读路径（检索）

- 本文不设计检索器：评测时**把全部记忆条目放进上下文**（§3）。因此它的结论对"检索是否命中"不敏感——它证明的是**库里内容本身在变坏**。
- 与我们最相关的一条对照：**episodic-only 基线**（原样把轨迹当 in-context 示例）在 WebShop / ALFWorld / AppWorld 上与四个 lesson 式固化器打平甚至更好（Table 4，被轨迹基线打败的固化方法在表里标 `(-)`）；作者由此主张：**任何依赖蒸馏的记忆方法，都必须先和"它蒸馏的那堆原始 rollout"比一场**（§4.2）。

## 6. 组织与关系

- 分组正确性是前提：模型**有能力**分组，但需要时间——Auto 模式下要到 **第 71 步（568 例）**才把 6 个问题类型都收进 buffer（§6.1）；而 Force 模式（每步 8 例就固化）经常跨类合并。
- 干扰的量化：ScienceWorld 15 任务切换序列上，逐步累积固化（Cumulative）比每任务单独固化（Fresh）**落后 +203 分**；用 LLM judge 给记忆条目打标，Cumulative 的"过度泛化"条目约为 Fresh 的 **5×**、"无用垃圾"约为 **20×**，且差距随任务数单调扩大（§6.2）。
- 与我们同形：把不同来源的东西**池在同一条记录**里再抽象（我们：一场对话里多个话题 → 一条 records；一批笔记 → 一条 topic 综述），就是"异构批次固化"。

## 7. 维护与自改进

- **原则（§5）**：episodic 与 schema-forming 两个角色**不要塌进同一个重写回路**；abstraction 应当是 **opt-in 且被 schema fit 设闸**，而不是每来一条经验就触发一次。
- 三条实测结论支持这个原则：① 增益主要来自 episodic 库（只留抽象、去掉 episodic 会掉回无记忆基线，Fig. 9a）；② **只管 episodic（连抽象都关掉）就追平或超过完整 Auto**（Fig. 9a）；③ 强制抽象不如"保留 episode"策略（Fig. 5，400 步）。
- 模型自己在有选择时也选 episodic-first：Auto 模式下会迅速把 episodic buffer 塞满、让 abstract store 保持稀疏（Fig. 7b）。
- 对照我们的维护动作：`superseded` / `archive`（移动而非删除）方向与"append-only + 剪枝有益"一致；但我们**缺**"固化闸门"与"固化时不看旧抽象"这两条。

## 8. 验证与质量门控

- 作者用"**用它们自己已解出的题**"和"**给标准答案**"两种方式消除了"经验本身没用"这一借口（§1、§4）；Fig. 2 的 Static 对照（同样轨迹、一次固化）在 R=10/50 轮后仍停在满分线上，说明退化来自**反复改写**而非数据。
- 统计面：10 次端到端重复（Table 2：无记忆 58.5±5.4 / 一次固化 55.1±4.9 / 十轮固化 38.5±5.3；pass@10 从 100% 掉到 60.6%）；多 backbone、多框架、多 benchmark 交叉。
- 可迁移的**验收设计**：把"原始轨迹直读"当成记忆系统的**必测基线**。我们目前所有门禁（`test-memory.mjs` / `engine-probe.mjs`）都只测注入与检索的**结构性质**，从不问"这一层抽象到底比不给更强吗"。

## 9. 成本 / 安全 / 隐私

- 本文是准确率/成功率的实验，不测 token 成本；Table 3 的 agent 实验隐含着"更大推理预算也治不好"。
- 安全面留了一句要害："可靠 agentic memory 需要能在**不覆盖它依赖的证据**的前提下固化的 LLM"（摘要）——与 Louck 2026 的"洗白"是同一问题的两端。

## 11. 评估方法

- benchmark：ALFWorld / ScienceWorld / WebShop / AppWorld / Mind2Web + 自建 **ARC-AGI Stream**（基于 ARCGEN，带已知潜在任务分类、程序化标准答案、可审计的记忆操作词汇）。
- 关键手法（我们能借）：**同一批输入轨迹、只改固化排程**（Static-All / Static-Group / Stream）⇒ 把"数据质量"这个混淆因素钉死；以及**组件剥离表**（Table 5 逐项去就地改写 / 去旧上下文 / 加剪枝）。
- 我们可借鉴的**被动信号**：抽象层的条目数与"跨族误合并"计数（对应我们体检的 `duplicates` / `methodologyInRecords`），以及"同一 pattern 在多少族里出现"。

## 12. 可迁移机制清单

1. **固化闸门（gate consolidation）**：把"写 records/topics"从"每轮可写"改成需要满足显式条件（新证据 vs 旧抽象的拟合度、是否新增族、是否只是复述）⇒ 对应 P4 与缺口 2。
2. **固化时不看旧抽象**：生成/更新记录时，把已有记忆索引从上下文里移出（或显式声明"仅作参考、不得复述"）。Table 5 的 B 行（旧库隐藏）是 70.0 vs 50.0 的差距，这是**最便宜也最容易被忽略**的一条。
3. **禁止就地重写，改 append + 剪枝**：结论变化时新增一条并让旧的 `superseded`，而不是改写旧卡正文；删（归档）不伤质量，改伤质量。
4. **异构批次先分组**：多话题对话 → 先分族再固化，禁止一次会话产出一条跨主题综述（对应我们 `methodologyInRecords` 的判据升级）。
5. **raw episode 当一等证据**：episodes 原文不仅"留档"，在结论性回答时应当能被直接引用（我们已有磁盘原文，但注入层只有索引行 ⇒ 需要显式的"回读原文"纪律或工具）。
6. **必测基线**：任何"记忆注入带来增益"的声称，都要与"直接给最近 N 条原始 episode"对照（对应我们从未跑过的诊断）。

## 13. 与 dsh-math-memory 的映射与差距

- **采纳（与本仓库 P4 同向，且给出比"降低权重"更根本的理由）**：P4「AI 归纳一律先写 inbox / `stage: draft`」不再只是"证据弱所以降级"，而是"**固化本身有损，触发次数越多越坏**"——闸门的作用是减少固化次数，不只是降低可信度。缺口 2（`ask` 的同意不落字段）因此升级为：**"要不要固化"必须落成卡上字段**。
- **采纳（新增机制，P1–P7 里没有）**：固化/写入时的**上下文隔离**——写新记录时不要把现有 records 索引连同小标题一起塞给模型（我们每次组装 system-prompt 都注入，`math-memory.mjs:4121-4133`）。这条与 P2（可信度进注入）**方向相反但互补**：P2 让模型在"用"记忆时降级引用，隔离让模型在"写"记忆时不受旧抽象锚定。
- **改造（P5 的"单源老化降权"）**：Zhang 的处方是"原始证据优先"，不是"给低权重"。降权会让检索少给，但仍允许旧抽象在上下文里参与新固化；更贴近证据的做法是**在固化环节把旧抽象从输入里移除**，而不是在排序上打折。
- **改造（体检项）**：`methodologyInRecords`（`:2055-2077`）现在是"一般性梳理落进记录层"的**事后报告**；Zhang 的异构批次结论支持把它提前成**写入前的分组检查**（P4 的 `stage` + 分族判据）。
- **不适用**：本文的"Force vs Auto"是**每步都能选动作**的 agent loop，我们没有这种逐步决策循环（我们的"步"是人机对话）；因此 Table 3 那种"自主 agent 管记忆"的设定不能直接搬，只能借它的结论（能力/预算不治病）。
- **不适用（证据强度）**：本文全部实验都在 agent benchmark 的**程序化任务**上，记忆是"LLM 自己写的 lesson bank"，**没有**任何实验测过"人类笔记 + AI 补全"的混合库。它证明的是**机制**（反复固化有损、就地改写最伤），不能直接换算成我们 vault 里的具体退化幅度。
