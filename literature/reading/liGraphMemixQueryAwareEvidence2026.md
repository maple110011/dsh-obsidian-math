## 1. 一句话定位

把长期多模态 agent 的**记忆选择**重构成「查询条件下的证据森林」组合优化：不在写时把历史压成通用摘要（贵且丢局部线索），也不只按相似度取 top-k（近重复挤占预算、低相似度互补证据永远取不到）；而是在查询到来时建一个有界候选图，用两个**职责分离**的验证器分别给「节点自身的支持度」与「相对锚点的增量价值」定价，再在读者预算 K 内解出「取哪些节点 + 哪棵信任边森林」，从而**把已验证的关系路径转换成可测量的低排名证据回收**。

## 2. 问题与动机

两条现有路线各自的失败模式（§1）：

1. **问题无关的离线压缩**（MIRIX / SGM / A-MEM / AUGUSTUS / M²A）：摘要、类型字段、链接笔记都在问题到达**之前**做 ⇒ 为避免遗漏必须处理整段历史，冷启动与更新成本高；「问题无关的压缩」还会丢掉事后才关键的视觉状态迁移与局部上下文。
2. **多模态 RAG**（MuRAG / Pensieve）：保留原始视觉访问、成本低，但**按相似度排序**会「过度选择近重复记录，同时漏掉不相似但互补的证据」——而回答常常需要**多条记忆联合**才有用。

## 3. 记忆结构

不是新的存储分层，而是把记忆单元当作**图的节点**、把「可能的上下文依赖」当作**边**，且**图不落盘**（查询时按需重建、用完即弃）：

- 节点：一条多模态记录 $e_i$，带多视图 $\mathcal U_i$（原图 / caption / OCR / 视频帧），初始分 $s_i(q)=\max_{u\in\mathcal U_i}\mathrm{sim}(h(q),h(u))$（式 3）。
- 边（式 4）：**schema 关系** $E_{\text{schema}}$（可观测交互结构：同 session、同地点…）+ **语义关系** $E_{\text{sem}}$（互为 $k$ 近邻，$k=8$）。
- 候选集（式 5）：top-$L$ 种子 ∪ $\le H$ 跳邻居 → $\mathrm{Top}_M$。**实测参数：$L=24$、$H=1$、$M=48$、读者预算 $K=10$**（§4.1）。编码器 `gme-Qwen2-VL-2B-Instruct`（1536 维）。
- 输出：森林 $(S_q,F_q)$，$|S_q|\le K$，且 $F_q$ 只取**已验证**的边。

## 4. 写路径（固化）

**空的**（这是设计选择，不是遗漏）：本文刻意不做写时生成式压缩，批评的正是那条路线。没有去重/合并/剪枝/演进机制，记忆库只增。唯一的写入侧工作是派生多视图表示（caption / OCR / 帧）——而 §A.1 明确：caption 生成只看图像与通用指令，**不看问题答案、gold 证据、评测注记或检索结果**（避免泄漏）。

> 对我们的意义：GraphMemix 的成本优势建立在「不写时压缩」之上，而代价是每次查询跑两个验证器 + 一个求解器（需 LVLM 调用）。我们相反：写入侧有零模型调用的确定性体检，读取侧是零模型调用的 BM25 + 读文件。**两边都在省模型调用，只是省在不同阶段**——所以它的机制只能取「结构」，不能取「验证器」。

## 5. 读路径（检索）

1. **多视图召回**（式 3）：各视图分别算相似度后**取 max**（max-pooling），只用于把候选**捞进来**，不用于最终排序。
2. **直接节点效用**（式 6）：listwise 节点验证器一次读 $q$ 与 $C_q$（**≤48 个候选** = 24 检索种子 + 图扩展），给每条候选「单独支持度」$v_i(q)\in[0,5]$，与检索分融合：
   $$p_i(q)=\sigma\big(\tau[\alpha s_i(q)+(1-\alpha)\tilde v_i(q)-\delta]\big),\qquad \mathcal U_{\text{node}}(S\mid q)=\sum_{i\in S}p_i(q)$$
   **实测参数 $(\alpha,\tau,\delta)=(0.8,5.2,0.7)$，等价于 $p_i=\sigma(4.2s_i+0.2v_i-3.6)$**（式 14–15；$v_i$ 先除以 5 归一）。注意权重极不对称：**检索先验占 4.2，验证器只占 0.2**——验证器是修正项，不是主排序。
   - 候选表示（§A.4）：匿名 ID + 模态标签 + 日期 + 位置 + **query-aware 片段（≤420 字符正文 + ≤120 字符清洗后 OCR）**；JSON 严格解码，未知/重复 ID、越界分数一律拒绝，格式错误最多重试 3 次，**被省略的候选记 0 分**。
3. **锚点条件下的关系验证（ECV）**（式 7–9）：取高置信锚点集 $A_q$（**从冻结的检索结果确定性构造，不含节点验证器分数**——避免循环选择），只看锚点↔候选的 schema 边，一次 listwise 调用为每条候选挑「最能解释其增量」的锚点、给增量分 $s^{\text{inc}}_{ai}$、归入六角色：`new_fact` / `clarification` / `corroboration` / `redundant` / `conflict` / `irrelevant`。**只保留「最优锚点边 + 正分 + 前三种角色」**，形成 $E^{\text{trust}}_q$。
   - 边上定价：$w_{ai}=w^{\text{schema}}_{ai}s^{\text{inc}}_{ai}/s_{\max}$（$w^{\text{schema}}_{\max}=0.99$），$c_{ai}=-\log w_{ai}$，$C_{\text{edge}}=\lambda\sum c_e$（$\lambda=0.1$）。
   - 两个验证器**并行执行**，ECV 不覆盖节点分数；edge-only 模式下**代码强制** `direct_support=0`（不只靠提示词）。
   - **效果（Table 6）**：每题边数 6.07–7.34 → **0.25–1.47** 条，连通分量 2.66–3.93 → 8.53–9.75，Hit@10 反而 +1.83~+5.60。
4. **独立链成本与自适应基数**（式 10–12）：$C_{\text{open}}=\kappa\,m(S,F)$（$m$=连通分量数=独立证据链条数）。边成本非负 ⇒ 最优 $F$ 可取森林 ⇒ $m=|S|-|F|$；定义结构增益 $B_e=\kappa-\lambda c_e$ 后目标等价于
   $$\sum_{i\in S}\big(p_i(q)-\kappa\big)+\sum_{e\in F}B_e(q).$$
   **语义**：孤立记忆贡献 $p_i-\kappa$，只有能自证「值得单开一条证据链」才留下；通过信任边挂到已有分量的记忆省下一次开链成本，边际贡献变成 $p_i-\lambda c_e$。**自适应 k 由此而来，不需要额外的每节点惩罚项。** 实测 $\kappa_{\text{prop}}=0.2$（定基数阶段）、$\kappa=0.12$（精确细化阶段）。
5. **求解**（式 13）：两阶段确定性求解。① 定基数：从 top-$K$ 初始化，每次评估一次 selected↔unselected 交换，**用 Kruskal 精确重算每个提议集的最大权森林**，直到 1-swap 局部最优（Figure 2：增益在约 6 次接受的交换后饱和）；② 在冻结的提议集内**精确**解变量基数问题（枚举非空子集 + Kruskal）。平手规则：**优先更少记忆，再优先更早的提议名次**。
6. **序列化（§A.5 原文）**：每个连通分量取**效用最高的节点为根**；分量按根效用排序；分量内**按宽度优先遍历**；平手按节点效用、再按原始检索顺序。读者最多收到 $K$ 条规范记忆。

## 6. 组织与关系

- 关系有两类语义（schema 可观测 + 语义互补），**关系的可信度是查询条件化的**：§4.4.3 的固定边对照实验给所有可接受边一个 query 无关的 0.99 可靠性，Hit@10 反而更低。
- **★ 最有价值的反例（§A.6，Table 9/10）**：在**冻结候选与节点效用**的控制实验里（固定 $K=10$、$M=48$），**通用多样性/覆盖目标全部不优于朴素 top-K**：Node Utility Top-K 56.87 / MMR 56.84 / Rel.–Red. 56.82 / DPP 52.69 / Facility Location 56.80；而用**已验证关系**的是 Anchor–Neighbor 57.33 / ECV Pointwise 57.26 / Greedy Forest 57.29 / **Forest Proposal 57.74**。
  - 换成**净回收**（Δ = 新捞到的低排名 gold − 被挤掉的原有 gold，式 16，Table 10）：MMR **−6**、Rel.–Red. −4、DPP **−36**、Facility −2；Anchor–Neighbor +14、ECV Pointwise +12、Greedy Forest +18、**Forest Proposal +43**（其中 H2HMem +31，而通用选择器最多 +1）。
  - 结论：**「让列表更不相似」本身没有价值，甚至会伤害**；价值来自「把**已验证的关系路径**变成低排名证据的回收」。

## 7. 维护与自改进

**没有**。全文没有 audit / merge / promote-demote / prune / reinforce / antipattern 之类的记忆维护机制；记忆库只增。抗冗余、抗冲突的能力全部放在**查询时的角色门控**里（`redundant`/`conflict` 拿不到结构奖励），而不是写时清理。

## 8. 验证与质量门控

- 门控 = 两个验证器的**角色判定**：`redundant`/`conflict`/`irrelevant` **不是被删除**，而是**不能借边拿结构奖励**。
- 解析层也是门控：JSON 严格模式、未知/重复 ID 拒绝、分数域检查、**被省略的候选记 0 分**、格式错误重试 ≤3 次；ECV 的 `best_anchor_id` 必须落在该候选的 eligible 关系内；「空锚点/不合格锚点/非正角色配正分/正角色配零分」一律保守清空。
- **职责分离是实测决策**（§4.4.4，Table 7）：合并成一次调用（严格 keyed JSON 同时输出两个判断）反而更差；分离两调用 **macro Acc +2.00 / R@10 +3.00**（59.25→61.25 / 52.94→55.94），且两者无串行依赖、可并行，因此**不增加串行成本**。
- 评测自证：200 条分层抽样人工复核与 GPT-5-mini 判定**一致 194/200（97.0%）**；judge 只收到 question/instruction/response_type/choices/reference_answer/prediction，**不收到记忆、检索证据、验证器输出或私有推理**。

## 9. 成本 / 安全 / 隐私

- 成本主张（§4.3）：完整生命周期 = 消化全部历史一次 + 回答全部问题一次。ATM-Bench 上比 A-MEM / VimRAG / LightMem 分别缩短 **约 1.78× / 4.27× / 4.74×**，且准确率最高 ⇒ 位于经验 Pareto 前沿。另三个基准的估计：Mem-Gallery 2.19 h（7,944 记忆 / 1,711 问题）、MemEye 2.71 h（3,392 / 1,855）、H2HMem 3.44 h（7,078 / 1,982）。
- 查询侧新增成本：两次并行 listwise 验证器调用 + 一个确定性求解器；候选与 $K$ 都有界 ⇒ 成本不随历史规模增长。
- 隐私/安全：**未讨论**（无本地性、无 fail-closed、无敏感数据条款、无删除/遗忘机制）。
- 生成参数：三阶段均 32,768 上下文、temperature 0；验证器/ECV ≤8,192 输出 token，读者 ≤1,000。

## 11. 评估方法

- 四套长期多模态记忆基准（ATM-Bench / Mem-Gallery / MemEye / H2HMem）× 两个读者模型（Qwen3-VL-8B-Instruct、Gemma 4 12B Unified）× 固定 judge（GPT-5-mini，记录 prompt 协议版本与 SHA-256）；主指标 Judge Accuracy，各基准另报原生指标（EM / MCQ-EM 四选项轮换 / 停用词过滤 Recall）。
- **增量消融**（Table 3）：逐个加组件、每项贡献可归因——本文最值得学的评估工程。
- **证据可达性分层**（Table 4）+ **问题级回收**（Table 5）：用「可达性」而不是「命中率」描述检索失败的成因。
- **控制实验**（§A.6，Table 9/10）：**冻结候选与节点效用**，只比较选择器本身，并用**带符号的净回收 Δ**（式 16）替代单侧回收计数——这一步把「只是更不相似」与「真的捞回了 gold」区分开。**这是我们最该学的评估设计**。
- **行为审计**（Figure 2）：目标增益随交换次数的曲线 + 结构增益随接受边的累计曲线。
- **生命周期 Pareto**（Figure 3/5）：把「消化全部历史一次 + 回答全部问题一次」的墙钟时间与准确率联合绘制。
- 对**我们**最有用的被动信号：**可达性三分（Direct / Recoverable / No access）与净回收 Δ**——两者都能在真实 vault 上零 token 测。

## 12. 可迁移机制清单

1. **多视图 max-pool 检索分**（式 3）：同一条记录多视图各自打分取 max，而不是拼成一个 passage 再打一次分。→ `dsh/preset/note-tools.mjs` 的 `buildRecallDoc`/`rankRecallDocuments`：我们现在把 `title+hook+topic+body(≤800)` 拼成**一个** bag，长正文会稀释 hook 的强匹配。
2. **★ 关系证据优先于通用多样性**（Table 9/10）：**不要**引入 MMR / DPP 式的通用去冗余重排——控制实验里它们不优于 top-K（56.84 vs 56.87）且净回收为负（−6 / −36）。要做的是「用**已验证的关系**够到低排名证据」（+43）。→ `note_links` 顺链扩读 + `related` 双链的**查询门控**（见第 4 条）。
3. **锚点条件下的增量判定（六角色）**（式 7–8）：候选不是独立打分，而是相对已选锚点判断**新增/澄清/佐证/冗余/冲突/无关**，并且**只有前三种能拿到结构奖励**。→ `note_recall` 的返回结构：我们现在是扁平排名，没有「相对已选卡是冗余还是互补」。**注意落地方式**：这是**角色门控**（决定要不要采纳关系证据），不是「让列表更多样」的惩罚项。
4. **结构增益 / 开链成本**（式 10–12）：孤立证据要自证 $p_i>\kappa$，能挂到已选分量上的只算 $p_i-\lambda c_e$ ⇒ **自适应 k**，而不是固定 `maxResults`。我们的等价物：先取锚点，再按边际贡献决定是否继续加；「锚点」概念也解释了为什么 `related` 邻居值得一个名额。
5. **关系的可信度是查询条件化的**（§4.4.3）：静态高可靠性反而更差。→ 我们的 `related` 是静态双链，`note_links` 无条件顺链扩读；应加**轻量门控**（当前查询 token 覆盖度），把「结构相关」与「本题相关」分开。
6. **可达性分层 + 净回收 Δ 指标**（Table 4/5/10 + 式 16）：Direct / Recoverable / No access 三档 + 带符号的净回收。→ `scripts/qa/engine-probe.mjs` 增加零 token 断言：对每个 ground-truth，检查它是否在 top-10 之外但在一跳邻域内；**并统计「捞回一条是否挤掉了另一条」**（单侧计数会高估）。
7. **验证器职责分离**（§4.4.4）：把「直接支持」与「相对锚点的增量」分成两次独立判定，比合并成一次更好，且可并行。→ 若将来给 `note_recall` 加适用性判定，应做成**两级**而不是压成一个分数。
8. **有界候选 + 预算内序列化**（§A.5）：分量按根效用排序、分量内宽优先遍历、根在上下文之前 ⇒ 读者先看到直接锚点再看由关系捞回的补充。→ 注入/读取顺序可按 `related` 簇组织（先簇根、再补充）。
9. **解析层门控**（§A.4）：被省略的候选记 0 分而不是「未评分」；非法锚点/自相矛盾的角色-分数组合一律保守清空。→ 我们若加结构化输出解析，应照此**默认保守**（宁可少采纳，不可误采纳）。
10. **平手规则**（式 13）：同分时**优先更少记忆**，再优先更早名次。→ `rankRecallDocuments` 的排序稳定性与「宁可少注入」。

## 13. 与 dsh-math-memory 的映射与差距

| 维度 | GraphMemix | 我们现状 | 判定 |
|---|---|---|---|
| 记忆单元 | 多模态 record | markdown 卡片（records/topics/theorems/templates/strategy）+ episodes 原文 | 结构同构／多模态不适用 |
| 组织时机 | **查询时**组织，图不落盘 | 写时落盘（hook/related/source/index）+ 查询时 BM25 | **同向**：都拒绝写时生成式压缩 ⇒ 印证我们的路线 |
| 多视图 | 各视图打分取 max | `title+hook+topic+body` 拼成一个 bag 打一次分 | **采纳**（机制 1，纯本地零依赖） |
| 关系 | schema + 语义两类边，**查询条件化可信度** | `related`/`source` 静态双链，顺链扩读无门控 | **改造**（机制 5） |
| 冗余/冲突 | 查询时**角色门控**（不给结构奖励） | 写时 `superseded`/`duplicate_of` + 体检「疑似重复」；检索期无判定 | **采纳**（机制 3，但见机制 2 的警告：不要做通用去冗余重排） |
| 自适应 k | $p_i>\kappa$ 才单开链，否则按边际收益挂靠 | 固定 `maxResults` + 协议「读前 2-3 篇」 | **改造**（机制 4） |
| 验证门控 | 两个 LVLM 验证器（listwise，可并行） | 零模型调用；`verified` 三级 + 用户反馈 + 每日确定性体检 | 不改（红线）；但**职责分离**与**解析保守**可借（机制 7/9） |
| 维护/自改进 | **无**（只增档案） | 体检 audit + merge/promote/demote/prune/reinforce/antipattern | **反向**：这块我们强得多，不要削自己 |
| 评估 | 四基准 + 增量消融 + 可达性分层 + **净回收 Δ** + 生命周期 Pareto + judge 人工复核 | 零 token 探针（seed 8/8 + 真实 vault 12/12）+ 被动信号（空结果率） | **采纳**（机制 6 + §11 的「带符号回收」思想） |
| 成本模型 | 查询侧贵、写入侧免费 | 写入侧确定性体检、查询侧零 token | 对偶，**不适用**其求解器，只借结构 |
| 隐私/本地性 | 未讨论 | fail-closed、本地文件、无外部服务 | 我们更严 |

## 14. 行动项

（按性价比排序；**均不需要模型调用**。★ = 本版复读后新增/修正的判断）

1. **（探针，最高优先）`engine-probe.mjs` 加「可达性分层 + 净回收」**：对每个 ground-truth 判定 Direct（top-10 内）/ Recoverable（top-10 外、但在某个 top-10 命中的 `related`/`source` 一跳内）/ No access，并统计「捞回一条是否挤掉了另一条」的**带符号**净变化（照式 16 的精神，避免单侧计数高估）。零 token，直接量化我们 AGENTS.md 要求的「顺链扩读」到底值多少。**先测再改。**
2. **★（提示词/协议）明确写下「不要做通用多样性重排」**：GraphMemix 的控制实验（Table 9/10）证明 MMR/DPP 类目标不优于 top-K 且净回收为负。这条应进 AGENTS.md 的检索纪律或 design 文档，**避免未来有人凭直觉给 `note_recall` 加去冗余惩罚**。
3. **（检索）`rankRecallDocuments` 改为按视图打分后 max-pool**：视图 = {title, hook.pattern, hook.techniques, hook.applications, topic, body-head}，替代拼接。风险低（现有探针即回归网）。
4. **（检索）加**`related` **邻居的查询门控 + 锚点名额**：顺链扩读前算当前查询的 token 覆盖度；同时允许「已验证关系捞回的邻居」占用一个名额（对应 $p_i-\lambda c_e < p_i$ 的直觉：挂靠比单开便宜）。
5. **★（检索）若加适用性判定，做成两级而不是一个分数**：先判「这条自身是否支持当前挑战」，再判「相对已选卡是否增量」（机制 7）。同时把解析写成**保守默认**（缺失=0、自相矛盾=清空）。
6. **（文档）把「关系可信度是查询条件化的」写进 AGENTS.md §5 检索纪律**（一句话）。

不建议采纳：图优化求解器（Kruskal / 1-swap，我们候选是个位数）；两个 LVLM 验证器（违背「插件不调模型」）；多模态分支；「记忆只增不维护」的路线；**以及任何通用去冗余/多样性重排**（第 2 条的反例）。
