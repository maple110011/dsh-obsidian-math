## 0. 一句话

**把"用户手写数学内容"这块唯一没有机器的地纳入门控，而门控要做成"插件自己干、不问用户"的形状。** 现在缺的不是机制，是**范围**（体检不扫笔记与定理索引）与**分工**（一批本来可以机器做的事被写成了"等用户点 ✅"）。

---

## 1. 评价标准（用户 2026-09-18 明确）

> **插件的最大目标**：① 与用户一起沉淀打磨数学想法；② **把这个过程中耗费时间与精力的平凡工作做掉，让用户能专注思考**。所有需要用户手动操作的功能，都要服从这个目的。

据此把每个动作分三类，**判据是"这件事需要谁的判断"**：

| 类别 | 谁做 | 判据 |
|---|---|---|
| **A 记账** | **插件自己做，不问** | 答案**完全由已有数据推出**（索引、计数、格式、时间戳、双链可达性、等级与正文是否矛盾） |
| **B 判断** | **模型自己做，事后可纠** | 需要"看内容"，但不需要用户口味或授权（提炼、分类、合并、从已有笔记推导互证） |
| **C 裁决** | **必须问用户** | 需要**用户的数学判断**（这条对不对）或**用户的口味/授权**（是否改已采纳的记号） |

**现在的毛病**：一批 A 类动作被写成了 C 类。最清楚的一例见 §3.1。

## 2. 接口（框架；实现留空）

### 2.1 审查状态（四态，SAFE 的四态模型本地化）

**为什么是四态而不是"verified / unverified"两态**：SAFE 的实测表明"**表达不了**"与"**结论错了**"是两种必须分开记账的失败——它的形式化流水线本身会产出"看似合理但错误因而不可证"的陈述，所以**形式化失败不能读作 claim 错**。我们的对应：

| 状态 | 含义 | 处置 | 谁能给出 |
|---|---|---|---|
| `not-applicable` | 不值得判（定义、约定、纯转录） | 跳过，不进队列 | A（确定性分类） |
| `unverifiable` | **判不了**（无来源 / 超出可判定范围 / 缺工具 / 陈述有歧义） | **降级留档**，禁止以已证口吻引用 | A/B 的失败出口 |
| `verified:<level>` | 已判为真，level ∈ `{recomputed, cross-referenced, formally-checked, user-confirmed}` | 可依据 | A（前两级）/ C（后两级） |
| `refuted` | 已判为假 | 最高优先级的修 | A/B（+ C 确认） |

**接口纪律**：`unverifiable` 必须带**原因码**（`no-source` / `out-of-scope` / `tool-missing` / `ambiguous`）。**没有原因码的 unverifiable 等于丢弃**——这正是 Danus 用"repair hints"避免的事。

### 2.2 claim 台账（machine-side，用户零输入）

**位置**：`.deepseek/memory/theorems/_claims.md`（下划线名前缀让它被体检的卡片扫描跳过；详见 `verification-design-2026-09-18.md` §6.2）。
**一条的字段**（**框架**；字段先定，写入逻辑后做）：

```yaml
- id: claim-<slug>
  claim: "给定 <前提>，<结论> 必须成立"   # 可判真假的形状；写不成这个形状的走 not-applicable
  anchor: "统计学/概率论/好集原理"          # 指向笔记（人可核）
  source_hash: <登记时该笔记正文的哈希>     # 正文一变 ⇒ 判定自动作废
  status: verified | unverifiable | refuted | not-applicable
  evidence_kind: citation | recomputation | cross-source | formal | none
  evidence: "<凭什么：引了哪条 / 算了什么 / 与哪篇笔记互证>"
  depends_on: []                          # 该 claim 依赖的其它 claim id（级联的依据）
  decided_by: plugin | model | user        # 落实"判定与提议分离"
  decided_at: YYYY-MM-DD
```

**为什么不需要用户填**：`anchor`/`source_hash` 由工具写；`claim` 由模型从笔记里抽；`status`/`evidence_kind` 由 §2.4 的判定产出。

### 2.3 体检条目加两个字段（**这是"框架"的核心**）

现在体检产出的每条建议只有"对象 + 判据 + 证据"。加两个，成本极低，但它把 §1 的三类分工**变成数据**：

```yaml
decision_source: plugin | model | user    # 这件事该谁办
suggested_action: <机器标签>              # 建议的具体动作（如 relabel-index、merge-into、narrow-boundary）
```

**它解决什么**：现在面板的标题是「**需要你决定 N 件**」，而这个 N 把三类混在一起（`math-memory.mjs:2396-2401`：待重审 + 归档候选 + 疑似重复 + **下游待复查逐卡各算一件**）。有了 `decision_source`，面板可以说"**N 件我自己办、M 件助手办、K 件需要你**"——**用户看到的是真正需要他的那一小撮**。
**这是框架、不是实现**：字段先加、先只打标不改行为；等 §5 的方案批了再按标记执行。

### 2.4 判定与作废（数据流）

```
① 抽 claim（模型，从笔记/定理索引）
        ↓
② A 类确定性检查（插件）──有结论──→ 判 verified:recomputed / refuted
        ↓ 无结论
③ B 类判断（模型，读 source 链与相关笔记）──有结论──→ verified:cross-referenced / refuted
        ↓ 仍无结论
④ 标 unverifiable + 原因码  ←──── 这是"降级"的正解：降的是"可当依据的资格"，不是内容价值
        ↓
⑤ 任何时候笔记正文变了（source_hash 不匹配）⇒ 回到 ①，且列出下游 depends_on 待复查
```

**关键设计**：判定挂在**内容指纹**上。这是 Danus"内容寻址 + 级联撤销"的轻量形态，也是现在对"审过了所以以后都对"唯一的防护——**零成本，且不需要任何新功能**。

## 3. 现状核查：哪些"平凡工作"被推给了用户

按 §1 的标准逐条过现有功能。**只列"可省掉"的**，不列真正需要用户判断的。

### 3.1 ★ 最清楚的一例：`cross-referenced`（互证）被设计成"必须用户参与"，但它其实是可确定性检查的

- 协议原文（`vault-AGENTS.md` 第 61 行 / `records-readme.md` 第 61 行）："`verified` 只能写 `single-source`，**升级到 `cross-referenced`（与笔记互证）或 `user-confirmed`（用户确认）必须用户参与，不得自升**。"
- 而**互证是可以被机器查出来的**："这张卡的结论在你库里的哪篇笔记里也出现过"——这是**双链 + 文本比对**，属于 §1 的 A 类。
- 后果（**结构性的**）：新卡**永远**停在 `single-source`（初始值），于是体检的 `unverified`（单源 > 60 天）**恒久报同一批卡**，而唯一的出路是用户**逐张点 ✅**——**用户被要求做纯粹记账**。
- **本仓库既有原则本来就反对这种堆叠**：`handoff.md` §5 记录的实测失败模式是"**机制没人用**"（2026-09-10 复查：`verified: user-confirmed` 数量为 0、`last_wrong` 为 0、`needs_review` 为 0、`success_rate` 全 0），用户当时明确否决了"每轮新增必做步骤"。
- **本次实测再添一证**：`theorems/index.md` 第 5 行 `状态:已证` 与载体自述"**由 AI 撰写、不是我的原稿、请勿当作已证**"直接矛盾，而**没有任何机器发现它**（体检不扫这一层）。

⇒ **这条不是"要不要做新功能"，而是"把 A 类动作从 C 类里拿出来"**。它同时命中 §1 的两个目标。

### 3.2 其余"可省掉的手动活"清单

| # | 现在要求用户做的 | 实际属于哪类 | 能否机器做 | 风险 |
|---|---|---|---|---|
| 1 | 点 ✅ 把卡升到 `user-confirmed`（因为没有别的升级路径） | **记账**（互证可查） | 能（升级到 `cross-referenced` 由插件写，`user-confirmed` 仍留给用户） | 低（只影响排序与徽标） |
| 2 | 在面板逐张点「归档」处理 `unused` 卡 | 记账 | 能（`autoArchive` **早已实现**，只是默认 off：`math-memory.mjs:2216`） | 低（移动非删除、可逆、有 .bak） |
| 3 | 自己维护 `notation.md` | **记账**（收集）+ 部分口味（统一） | 收集能全自动；统一只报冲突 | 中（误报会污染记号表） |
| 4 | 自己把定理登记进 `theorems/index.md` | 记账（从笔记标题/定理框抽取） | 能（但当前 `structure` 档已是 auto，实际由模型写） | 低 |
| 5 | 点「归档 >90 天事件」按钮 | 记账 | **不需要改——它已经是自动的**（`settings.autoArchiveEpisodes` 默认 `true`，`main.template.js:142, 2682`）；面板上那个按钮是手动兜底。**这条从清单里划掉** | — |
| 6 | 每轮回答「要记吗」的 ask_user（`idea`/`fact`/`preference` 默认 **ask**） | 多为记账（"这条值不值得记"有既有判据） | 能（改成 auto，保留事后可纠） | 中（怕污染记忆层，所以**需要你拍板**） |
| 7 | 逐条读体检报告并决定处置 | 混合 | 能分流（§2.3 的 `decision_source`） | 低（只改呈现与分流） |

**注意第 6 条的现状**：`.deepseek/capture-policy.md` 的默认是 `idea/fact/preference = ask`，也就是**每轮对话本来就有一个弹窗**——这正是"平凡工作推给用户"的默认形态。它当初设成 `ask` 的理由是怕污染记忆层，所以这条**不能我一个人改**（见 §6）。

## 4. 评估：五级瀑布的成本与可行性

| 级别 | 手段 | 成本 | 可行性（本次实测） | 风险 |
|---|---|---|---|---|
| **T0** | 确定性文本/结构/图检查（缺口标记、等级与正文矛盾、断链、引文可解析、自引环、来源类型方向、空存根、内容指纹作废） | **零** | **高**：真实库里立刻能报出东西（§3.1 的矛盾、8 处真断链） | **误报**是主要风险：断链原始告警 82 处里**只有 8 处为真**（90% 误报）⇒ **过滤规则本身必须当被测对象** |
| **T1** | 双源/互证、定理库存在性（本地） | 零（插件）+ 少量模型 token | 高 | 低 |
| **T2** | 数值反例/代入 | 需 shell 平面（vault 内的 AI 没有 shell） | **实测有效**：一次 20 行代入确证了一处公式错；但**代入点必须覆盖非对称/边界/退化**（同一公式在 μ=0 时完全正确、μ=1 时差 16%） | 中：数值通过**不是证明**，只能记 `recomputed` |
| **T3** | 形式化（Lean 等） | 高 | **不做**：SAFE 自己也只有 72.2% 的步骤能形式化；我们无语料、无环境、插件不联网 | — |
| **T4** | 只能留档（单源、引文不可解析、超出范围） | 零 | 高 | **无**——但**必须可见**，不能假装可信 |

**分布估计（实测，N≈420 claim-unit / 105 篇）**：零成本确定性 ≈60% / 需模型判断 ≈36% / 需外部工具 ≈5%。**但要注意分母**：105 篇里有 **24 篇 < 120 字符、5 篇空白**，这类根本不需要审查。

## 5. 方案（分三档，按"风险 × 收益"排）

### A 档：低风险、明确收益——**已做 1 项，其余待你一句"可以"**

| 项 | 内容 | 为什么低风险 |
|---|---|---|
| **A1** | ~~导入器对"同一文献两张卡"出声~~ | **已做**（§7） |
| **A2** | 面板标题把「需要你决定 N 件」拆成"我自己办 / 助手办 / 需要你"三类（先只打标不改行为） | 只改呈现与字段，不改任何判定 |
| **A3** | `cross-referenced`（互证）允许**插件**写（"这张卡的结论在别处也出现"可确定性检测）；`user-confirmed` 仍只留给你 | 只放宽一个**较低的**等级；不动最高等级 |
| **A4** | `unused` 卡自动归档**默认打开**（实现早就在，只是默认 off；移动非删除、可逆） | 可一键关；只动"零使用 + >90 天 + 非用户确认"最安全档 |
| **A5** | 体检扫描范围纳入 `theorems/index.md` 与笔记（**只读、只报**），第一条规则 = 等级与正文矛盾 | 只报告不改；用真实实例即可测 |

### B 档：需要设计，收益明确——**建议做，但要你点头**

| 项 | 内容 | 需要你拍板的点 |
|---|---|---|
| **B1** | claim 台账 + 内容指纹作废（§2.2/2.4） | 台账是"新增一张机器表的成本"；你要同意它存在 |
| **B2** | 级联穿过笔记（现在 `depends_on` 指向笔记时是**死边**，见 `math-memory.mjs:155, 2074-2090`） | 无争议，但改的是核心体检 |
| **B3** | `notation.md` 的**收集**全自动 + 只报真实冲突（不要求你先填表） | 只有你能决定"哪些该统一"；机制只负责发现 |
| **B4** | 数值代入（T2）的作业规范 + 一个真实反例回写笔记 | 需要"在 vault 外的会话里跑"这一步，属于跨平面操作 |

### C 档：**不做**（附理由，防止以后重复提议）

- **Lean / 形式化集成**：成本高、表达范围有限、失败模式会误导（SAFE 的四态正是为消化这种误导而存在）。
- **自动改写你的笔记**：与本仓库"只报不改"的纪律冲突。
- **"同一模型再审一遍"**：SAFE 的整条论证说明它只能给出置信度、给不出证据（同一个模型会犯同样的错）。
- **确定性的语义判定**（插件不调模型是红线）。
- **新的记忆层/新面板**：claim 审查是**既有体检的一段**。

## 6. 需要你决定的问题（我按重要性排，回答任意几条都行）

1. **`cross-referenced` 能不能让插件写？**（A3）这是 §3.1 那个结构性陷阱的解药。若你担心"机器乱升等级"，替代方案是：插件只写**证据**（`evidence: 与笔记 X 互证`），等级仍由你一句话升——但那等于保留手动活。
2. **能不能把体检扫描范围扩到笔记与定理索引？**（A5）这会把"你手写的内容"第一次纳入机器视野。**只读、只报**，不改你的文件。
3. **`idea`/`fact`/`preference` 的默认档位要不要从 `ask` 改成 `auto`？**（清单第 6 条）现在**每轮对话默认有一个"要记吗"弹窗**。改成 auto 就少一个弹窗，代价是记忆层可能多进一些东西（事后可用 ❌ 纠）。
4. **`unused` 自动归档默认打开？**（A4）
5. **claim 台账（`.deepseek/memory/theorems/_claims.md`）要不要建？**（B1）它是所有后续判定的落点；不建就只能继续把判定塞在卡片 frontmatter 里。
6. **术语统一你能接受的最低参与度是什么？** 三个选项：(a) 完全不管，只在体检里看到"发现 3 组混用"；(b) 只在你**新写**笔记时提示一次；(c) 你愿意偶尔回一句"这三套分别是什么"。（我的建议是 (a)+(c)：机器只发现，你只裁决。）

## 7. 本轮已做的"低风险、收益明确"的事

**只做了一件**，按"小步快跑、按性质分别提交"的要求单独成一个 commit：

- **导入器对"同一文献两张卡"出声**（`scripts/lit-import.mjs` + `scripts/lib/lit-index.mjs` 的 `findDuplicateEntries`）：按 DOI/标题（归一化）比对"本次要导入的条目"与"库里已有的索引"，命中就打 warning 并写进 `.manifest.json` 的 `warnings.duplicateEntries`。**只报不自动合并**——保留哪一张、另一张怎么处理需要判断，静默合并会丢掉证据弱的那一方的来源。

  - 断言 11 → **15**，并做了**变异验证**（让 `findDuplicateEntries` 恒返回 `[]` ⇒ 3 条新断言红；恢复 ⇒ 15/15）。
  - 这也顺手补上了文档里承诺却一直没落地的那半句：`literature/README.md` 的「同一篇论文不建两张卡」约定现在**有守卫**了。
