## 0. 一句话回答

**能改进，而且改的是一处方向：把「降低 AI 笔记的权重」换成「把来源和结局记下来」。**

四篇从四个不同侧面指向同一个结论：**问题不在"给旧内容打多少分"，而在"这条内容是谁写的、后来帮没帮上忙"这两件事根本没被记录。**
- Zhang：坏在**写路径**——反复固化、就地改写（Table 5：默认 43.2 → 禁就地改写 50.0 → 旧库隐藏 70.0 → 原始轨迹 76.6）；排序上的"降权"改不了写入时就已发生的损坏。
- Xiong：坏在**把"被命中"当质量**（experience-following 相关最高 0.95；冻结记忆在三个环境里赢过 add-all）。给 `uses` 降权仍是"用一个不含质量信息的信号去调另一个"，缺的是「暴露 × 结局」的**配对样本**。
- Louck：坏在**用内容/血缘派生可信度**（机检分离定理 T1）；我们体检里"另一份文档出现同一 pattern ⇒ 自动升 ⚖️互证"正落在它定义的「制造共证」通道上；提权必须由**构造上独立**的来源给出，且计数不能从文本重算。
- Dash：坏在**写通道太多、太自动**（四条写通道 × 九条结构脆弱性；「重复被当作重要性/可信度」与“执行没报错＝被验证”都是它点名的脆弱性），而它给的三条防御方向**全部零实验**。

**同时，既有评估的主结论没有被推翻**：入口仍是"已经沉淀进记忆层的东西"，不是"你的笔记"。四篇里**没有一篇**测过"人类笔记里的自造符号/未厘清的想法"——用户问题里"自造符号"那一半，仍只有我们自己仓库的 `notationConflicts` 证据，**没有外部文献支持**。

## 2. 三件事被证实（既有结论被加强）

1. **"AI 反复改写笔记会让内容变坏"从合成夹具升级为有大样本实验的机制结论。** 既有评估 §1.3 的证据是**排序反转**（单源 AI 卡 0.9363 > 用户确认卡 0.9173），只能说明"排序把人误导"；Zhang 直接测**内容本身**变坏：同样的轨迹池、只改固化排程，Stream 比整池一次固化掉 17–38 分（Fig. 3），19 题从 100% 掉到 52.6%（Fig. 2），7 个框架 / 5 个 backbone / 自主 coding agent 全部"先升后降"（§4.3、Table 3）。**这回答了"会不会"：会，而且是"越写越坏"，不是"排错序"。**
2. **"检索命中会自我强化"被独立量化，并改名成 experience-following。** Xiong 证明"检索到的输入与当前 query 越像，输出被执行得越像"（r 最高 0.95），并给出两个后果：误差传播、错位的经验回放。既有评估缺口 5（`uses` → `hookPrior`）由此从"我怀疑的闭环"变成"别人测出来的性质"。
3. **"把记忆当已沉淀事实注入"是有害形态，不只是措辞问题。** Dash 的两条脆弱性与我们同形：V-S5「执行没报错＝被当成验证」（我们的 `success_rate` 只由用户点 ✅/❌ 驱动，真实 vault 里从未被使用——坑 35）；以及 **「重复被当作重要性/可信度」**（我们的自动互证就是"在两处看到同一 pattern"）。
4. **"内容派生的可信度不可靠"有了形式化结论。** Louck：T1 机检证明"以内容、或以内容可导出的血缘边为判决依据"的门是可被洗白的；T3 要求"写入时绑来源 + 独立共证"。我们的 `hook.verified` 本身是标签，但它的**升级路径**（内容比对）与"来源不在存储里"（缺口 3）正落在 T1 的失效类里。

## 3. 三件事被修正（既有结论要改口）

1. **既有评估 §5 把「自动互证升 ⚖️」列进了"系统能自己降噪"——这一条要改口。**
   既有文里写：体检凭"另一份文档里出现了同一 pattern/技巧"就把 `single-source` 升到 `cross-referenced`，并把它算作"系统自己能降噪"。Louck 的 L-c（制造共证）与 Dash 的 Salience-Driven Compaction（**重复 ≥3 次 ⇒ 被当成重要性**）说明：**"重复出现"是可以被制造出来的信号，不能当独立证据**。
   改口方向：⚖️ 从"系统自己降噪"移到"**需要改判据才能成立**"——除非两个来源**不共享上游**（不同 episode / 不同原始出处），否则只能显示为"相关重复"而不计票。
2. **缺口 5 的病根不是 `uses` 权重太高，而是没有配对样本。**
   我们的 `uses`（被检索命中几次）、`success_rate`、`gain` 是三个**独立字段**；Xiong 的效用是「每次暴露 × 那次结局」的**配对**均值（§4.1 式 2），没有配对就永远算不出"这条记忆有用没有"。所以"给 `uses` 降权"是治标：它压掉的是暴露量，不是错误率。**要补的是把结局回填到命中记录上。**
3. **P5②「单源老化降权」的优先级应低于「写路径的固化闸门」。**
   Zhang 的处方是"原始 episode 当一等证据 + 固化显式设闸"，而不是"给旧抽象打低权重"；Table 5 还给出组件排序：**就地重写是单项最伤**，而**剪枝（删而不改）反而有益**。降权属于检索侧微调，改不动写侧已经发生的损坏。

## 5. 不能引用的四处（防过度引用，逐条来自研读记录 §15）

1. **Louck 不能用来回答"我会不会越看越搞不懂"。** 它显式把**非后果性的答案偏置（answer-bias）划出范围**（§VI 末、§IX(a)：只守 retrieval→action，不管自由文本回答）。用户的抱怨正是 answer-bias ⇒ 它只能支撑"内容派生的可信度信号不可靠"，**不能**支撑"AI 笔记会让人理解出错"。
2. **Louck 的保证在我们这里只能部分成立。** 它的前提 A1 是"来源标注来自**已认证通道**"（mTLS / audience-bound OAuth / 签名响应）；我们的 vault 没有认证通道（内容可能是用户粘贴、剪藏、AI 写的），`origin` 只能退化为"写入者自报 + 通道推断"。**不能声称拿到 0% 那种强度的保证。**
3. **Xiong 不能支撑"加 verified 字段有用"或"该降级 AI 产物"。** 它的 strict 评估器是**ground-truth oracle 模拟**（§3.1），不是"用户确认"；全文没有 verified / 说话人来源 / 注入层这三个变量；也明确不含合并、摘要、反思、去重（Limitations）。
4. **Dash 的 §5 三条防御方向零实验**（收窄写策略 / 来源隔离+provenance / 写后监控），"激进读写⇒更易被利用"是 **n=2 的两 agent 对比、非消融**，且单模型、无置信区间 ⇒ 只能当设计原则的参考，不能当因果律或效果证据。
5. **Zhang 的全部实验在程序化 agent benchmark 上**（记忆是 LLM 自写的 lesson bank），**没有**"人类笔记 + AI 补全"的混合库 ⇒ 可迁移的是机制（反复固化有损、就地改写最伤），**不可**换算成我们 vault 的具体退化幅度。
6. **四篇都没有测"自造符号/未厘清想法"这一半**（`notationConflicts`、`noteClaims` 那一族仍只有库内证据）。

## 7. 「如何规范 AI 的记录」草案（提案，未实施）

八条，全部只约束**写路径**，不改变既有卡的存储格式（老卡走"来源未知"的 fail-closed 显示，不静默降级——照 `design.md:141` 与 P4 缺省取值的同一条纪律）：

1. **每条 AI 写入必须带来源**：`origin` 由宿主写入（`user` / `agent` / `imported`），模型不能写、不能改；缺省显示"来源未知"，不假装是用户说的。
2. **结论变化只追加，不改写旧正文**：新增卡 + 旧的置 `superseded`（我们已有这条原语，只是没有写进协议）；剪枝（归档）可用，就地重写不用。
3. **固化要显式触发**，不是每轮对话后自动写；固化时上下文**不含旧抽象索引**（或显式标注"仅参考、不得复述"）。
4. **一条记录只服务一个族**：多话题会话先分组再固化；跨族综述必须拆成多条（对应 `methodologyInRecords` 的升级）。
5. **记录终点而不是只记起点**：每次 `note_recall` 命中记一笔，并把那一轮的结局回填；`uses` 只作暴露量、不作质量。
6. **提权需要独立来源**：`single-source → cross-referenced` 的两个来源必须不共享上游；同源重复显示为"相关重复"、不计票；计数由宿主维护，不从正文重算。
7. **用户的 ✅ 与内容绑定**：内容一变，旧 ✅ 失效（照 Louck 的 action-bound single-use token 形态）。
8. **任何一条规范改动都要同时报"合法效用不降"**：借用 Louck 的反同义反复控制——"什么都不信"也能刷出好看的指标。
