## 1. 这是什么

`dsh-obsidian-math` 是同一个系统的两种发布形态：

| 形态 | 面向谁 | 作用 |
|---|---|---|
| **Obsidian 社区插件** | Obsidian 用户 | 在右侧栏嵌入 dsh Web 界面，自动启动/管理 dsh 服务，自动初始化记忆模板，**不需要任何 cmd 窗口** |
| **dsh 插件（npm 包）** | dsh 用户 | 把 `obsidian` agent preset 与 `obsidian` profile 安装进 `$DSH_HOME`，可用 `dsh --profile obsidian` 启动 |

Agent 刻意保持**最小工具集**：`read / write / edit / glob / grep / read_image / ask_user_question`。没有 shell、没有网页工具、没有子代理——所有修改都只发生在你的 Obsidian vault 内。

## 2. 准备工作

| 要求 | 说明 |
|---|---|
| Obsidian 桌面版 | 社区插件形态需要 |
| Node.js ≥ 22.5 | 记忆插件需要 `node:zlib` 的 zstd 支持 |
| DeepSeek Harness | npm 全局 `@deepseek-ai/dsh`，或任意本地安装（能被 `dsh` 命令找到，或在插件设置里填路径） |
| DeepSeek 模型配置 | 在 dsh Web 的 Models 页面，或 `$DSH_HOME/settings.yaml` 中配置好 provider/model |

## 3. 安装方式 A：Obsidian 社区插件（推荐）

### 3.1 安装

1. Obsidian → **设置 → 第三方插件 → 浏览**；
2. 搜索 **DSH Obsidian Math Assistant**，安装并启用；
3. 重启 Obsidian。

> 手动安装：把 GitHub Release 中的 `main.js`、`manifest.json`、`styles.css` 复制到
> `<vault>/.obsidian/plugins/dsh-obsidian-math/`，然后在“已安装插件”里启用。

### 3.2 首次运行会发生什么

- 插件**自动检测 dsh** 安装位置（按顺序：插件设置里的路径 → `DSH_HOME` 的上级目录 → npm 全局目录 → `PATH` 中的 `dsh` 命令）；
- 自动在 `$DSH_HOME` 写入 `obsidian` agent preset 与 profile（**只补缺失文件**，不会覆盖你已有的配置）；
- 自动在 vault 写入记忆模板：`AGENTS.md` 与 `.deepseek/` 目录（同样只补缺失）；
- 自动启动 dsh 服务（默认端口 `3180`）。

### 3.3 插件设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| Port | `3180` | 本地端口，与默认 `dsh web` 的 3080 互不干扰 |
| dsh installation directory | 自动检测 | 例如 `E:\software\deepseek-harness`；旁边有 **Detect** 按钮 |
| DSH_HOME | 环境变量或 `~/.dsh` | harness 主目录 |
| Start service automatically | 开 | Obsidian 启动后自动拉起服务 |
| Initialize configuration automatically | 开 | 首次运行自动补齐配置 |
| Show ribbon icon | 开 | 左侧 ribbon 的一键按钮 |
| Keep service alive when Obsidian closes | 关 | 开启则关闭 Obsidian 时不杀服务 |

### 3.4 为什么默认端口是 3180，而不是 dsh 默认的 3080？

- dsh 的 **web** profile（日常 coding 模式）默认绑定 `127.0.0.1:3080`；
- 本插件启动的是**另一个独立 profile**（`obsidian`），它也是一个独立进程；
- 两个进程无法同时占用同一个端口，若都用 3080，后启动的一方会报 `EADDRINUSE`；
- 所以默认取 `3180`：**Obsidian 助手与日常 `dsh web` 可以同时运行、互不干扰**；
- 如果你不用 `dsh web`，或者有别的端口规划，可以在插件设置里改 Port，或命令行 `dsh --profile obsidian --port <端口>`（改了端口记得同步插件设置）。

## 4. 安装方式 B：dsh 插件（npm）

```bash
# 1. 全局安装 + 一键初始化（--vault 同时创建 vault 记忆模板）
npm install -g dsh-obsidian-math
dsh-obsidian-math install --vault "D:\Obsidian笔记数据库"

# 2. 启动
dsh --profile obsidian --port 3180
```

也可以像普通 dsh 插件一样安装（postinstall 会自动执行安装器）：

```bash
dsh plugin --profile obsidian add dsh-obsidian-math
```

安装器命令：

```bash
dsh-obsidian-math install --vault <vault路径>   # 安装（幂等，保留用户修改）
dsh-obsidian-math install --force              # 覆盖安装
dsh-obsidian-math status                       # 查看安装状态
```

安装器会创建：

- `$DSH_HOME/.agent-presets/obsidian/`：`preset.yml`、`agent.cordis.yml`、`obsidian-memory.mjs`
- `$DSH_HOME/profiles/obsidian/`：`package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-workspace.yaml`
- `<vault>/AGENTS.md` 与 `<vault>/.deepseek/**`（给了 `--vault` 时）

> 记忆插件是**路径无关**的：vault 自动取会话的工作目录（或 `DSH_OBSIDIAN_VAULT`），历史会话自动取 `$DSH_HOME/sessions`（或 `DSH_SESSIONS_ROOT`）。

## 5. 首次配置与一键按钮

1. 启动 dsh 服务（插件自动，或命令行）；
2. 点左侧 ribbon 的 **message-square 图标**（或命令面板运行 **DSH Math Assistant: Open DSH Math Assistant**）；
3. 首次打开后把标签页**拖到右侧边栏**，Obsidian 会记住位置——以后每次点图标都在右侧出现；
4. 在 dsh Web 左侧工作区列表选择你的 Obsidian 库，新建会话；
5. 第一次对话建议说一句验证链路的话，例如：
   > “读一下我的记忆文件，然后给我一句话概览。”

## 6. 日常使用

### 6.1 记忆与回顾（解决“问了又忘”）

- 新会话第一句话不需要交代背景；系统提示已自动注入画像、主题导航、近期事件、备忘录状态与历史问答线索；
- 想回忆旧内容时直接问，例如：
  - “我们上次讨论 X 的时候，结论是什么？”
  - “我以前对 Y 的记号是怎么约定的？”
- AI 会先按检索路由 grep `episodes/` 或读主题文件，检索不到会明说“记忆里没有”，不会编造。

### 6.2 笔记写作（直接在侧栏完成）

| 你说 | AI 做 |
|---|---|
| “帮我理一下这篇笔记的思路该怎么写” | 复述结构，给出 2-3 个重组方案让你选，不直接大改 |
| “第 3 节细节我不想写，帮我补” | 直接读笔记补写，补丁标注 `<!-- AI 补全 -->` |
| “审阅一下这篇笔记” | 按“逻辑错误 > 结构 > 记号表述 > 小瑕疵”分级列出问题 |
| “找找这篇笔记有什么问题” | 检查假设、定义顺序、记号一致性、例子与定理匹配、双链断裂 |

所有修改都限定在 vault 内，可回看、可撤销。

### 6.3 关键想法捕获

- AI 会主动识别“一般性的数学思路、方法、技巧、观点”，在回复末尾给 `💡 可捕捉的想法`；
- 用 `ask_user_question` 弹窗问：**写入新 memo / 并入已有 memo / 稍后 / 忽略**；
- 想省事就说一次：“以后关键想法默认直接写入备忘录”，AI 会记入长期授权。

## 7. 四层记忆系统

记忆设计依据 [arXiv:2606.24775](https://arxiv.org/abs/2606.24775)（Agent 记忆系统四模块框架）：**原文证据优先于摘要、写时保留而非早过滤、检索先粗后细、维护只做局部更新。**

| 层 | 文件 | 内容 | 规则 |
|---|---|---|---|
| 语义层 | `memory/profile.md` | 稳定偏好、记号、长期授权、当前有效事实 | 只放“现在成立”的结论 |
| 导航层 | `memory/topics/` | 主题索引 + 主题细节 | 索引只做路由，细节进 `<topic>.md` |
| 证据层 | `memory/episodes/` | 每轮对话的原始事件卡 | append-only，不删除、不重写历史 |
| 想法层 | `inbox/` | 待打磨想法（memo） | 状态流转 `inbox → polishing → done` |

系统提示只注入**导航层**（画像 + 主题索引 + 事件时间线 + 备忘录状态 + 最多 6 组问答线索），预算固定；细节证据在磁盘上按需 grep/read。

记忆维护规则（AI 自动执行）：

1. **双写**：每轮收尾先往当天 episode 追加事件卡（保留用户原话、结论、事实修正），再局部更新 profile/topics；
2. **版本化更正**：旧事实标 `~~旧值~~ → 新值（日期）`，不抹掉历史；
3. **归档**：episodes 超过约 40 个文件时，最旧的原样移入 `archive/`，只更新索引。

## 8. 备忘录：捕获、关联、主动提醒

### 8.1 生命周期

```
inbox（待打磨）→ polishing（打磨中）→ done（已归入正式笔记）
```

每条 memo 一个 md，状态在 frontmatter，总索引在 `inbox/index.md`。

### 8.2 自动维护（AI 代劳）

- 新想法写入前先做**关联检测**：高度相关 → 并入已有 memo 的“关联观察”；中度相关 → 新建并互相补 `related` 双链；独立 → 新建；
- 对话中出现相关证据时，自动追加到对应 memo 并更新 `updated`；
- 打磨完成后：`done` 的升华内容写入正式笔记前仍会问你，memo 保留去向链接。

### 8.3 主动提醒（插件保证）

- 插件每轮扫描所有 memo 的 frontmatter，计算陈旧度：
  - `polishing` 超过 **3 天**未更新 → 提醒候选；
  - `inbox` 超过 **7 天**未更新 → 提醒候选；
  - 今天已提醒（`last_reminded` = 今天）自动跳过。
- 当本轮讨论与某条 memo **明显相关**（新证据、新反例、可推进待打磨清单）时，AI 在回复末尾给出：

```markdown
🔔 备忘录提醒
- [[slug|标题]]：你刚说的 X 正好补上了它的一个缺口
```

并用 `ask_user_question` 问：**现在打磨 / 稍后 / 忽略**。

- 提醒纪律：每条每天最多一次，每轮最多 2 条；可在 profile 的“长期授权”里改频率（例如“只在明确相关时提醒”）。

### 8.4 打磨

用户同意打磨时，AI 会：读 memo 全文 + 关联笔记 + 相关 episodes → 联想/检验/泛化 → 把进展写回“打磨记录” → 足够成熟则建议归入正式笔记（写入前询问）。

## 9. Vault 目录速查

```text
vault/
  AGENTS.md                          工作协议（自动加载；改它 = 改 AI 行为）
  .deepseek/
    memory/profile.md                语义层：用户画像（AI 维护，可直接编辑）
    memory/topics/index.md           导航层：主题路由索引
    memory/topics/<topic>.md         主题细节
    memory/episodes/index.md         事件时间线
    memory/episodes/YYYY-MM-DD-*.md  原始事件卡（append-only，勿删）
    memory/episodes/archive/         归档
    inbox/index.md                   备忘录状态索引
    inbox/<slug>.md                  单条想法（关联观察 + 待打磨 + 打磨记录）
    cache/                           历史会话索引缓存（机器生成，勿动）
```

`.deepseek` 会随你的 Obsidian 同步方案（如 remotely-save）一起同步；不想同步缓存可在同步设置里排除 `.deepseek/cache`。

## 10. 常见问题排查

| 现象 | 处理 |
|---|---|
| 侧栏页面空白/连不上 | 确认服务在跑：浏览器打开 `http://127.0.0.1:3180`；插件设置页点 **Start service** 并看 Recent service log |
| 插件提示 `dsh not found` | 设置页点 **Detect**；仍失败就手动填 dsh 安装目录（如 `E:\software\deepseek-harness`） |
| 新会话工具不对/没有记忆 | 确认会话使用 **Obsidian 笔记助手** preset；空白会话可在设置里切换，开始过对话的会话不可切 |
| 改了 `AGENTS.md` 不生效 | 新会话即生效；改了 preset 插件文件需要重启 3180 服务 |
| 端口冲突 | 换端口：改插件 Port 设置，或命令行 `dsh --profile obsidian --port 3181` |
| 想同时用 coding 模式 | 继续用 `dsh web`（3080），两者互不影响 |
| 备忘录提醒太频繁 | 在对话里说“备忘录只在明确相关时提醒”，AI 会写入 profile 长期授权 |
| vault 路径换了 | 无需改配置：记忆插件自动取会话工作目录；或用环境变量 `DSH_OBSIDIAN_VAULT` 覆盖 |

## 11. 更新、卸载与数据安全

**更新**

- Obsidian 插件：随社区插件市场自动更新（每次发布新 Release 即可）；
- dsh 插件：`npm update -g dsh-obsidian-math && dsh-obsidian-math install`（安装器只覆盖代码，保留你的配置与记忆文件）。

**卸载**

- Obsidian：设置 → 第三方插件 → 停用并卸载即可；
- dsh：删除 `$DSH_HOME/.agent-presets/obsidian` 与 `$DSH_HOME/profiles/obsidian` 两个目录。

**数据安全**

- 服务只绑定 `127.0.0.1`，不对外暴露；
- 所有记忆都是 vault 内 markdown：可读、可改、可版本管理、可随笔记同步；
- 历史会话索引缓存在 `.deepseek/cache/`，从不离开本机。
