# 检索 v3 提案（第二版：端到端审视 + 「统一入口、粗筛-精读」架构）

> 状态：**提案定稿 v2，待用户抉择后实施**。背景：用户明确「现状不必维持、完全推倒重来可接受，优先保证 AI 正确且快速检索到相关信息，愿意花 tokens 保效果」。
> 依据：AgentIR（2603.04384）、RaDeR（2505.18405）、LeanSearch v2（2605.13137）论文笔记见 references.md §7-9；对检索/关联/提取/整理四层代码与真实 vault 状态的逐行审视。

## 1. 检索的本质（决策者速读）

- 上下文装不下整个 vault，任何方案都必须「先选、后读」。
- 「让 AI 全局检索」是一个循环：想清楚查什么 → 选候选 → 读候选 → 判断 → 不够则换查询。「打分器」只是循环里「选候选」的排序规则，二者不互斥。
- 三种排序器对比：

| 排序器 | 能力 | 成本 | 角色 |
|---|---|---|---|
| BM25（词法） | 词面匹配，稀有词加权/词频饱和/长度归一 | 0 token、0 部署、毫秒 | 经典强基线，粗筛 |
| 本地 embedding | 语义相似（词面不同意思相关也能召回） | 0 token、约 95MB 模型 | 扩大粗筛召回 |
| LLM 重排 | 亲自读候选判相关，最准 | 按候选数烧 token | 精读/挑选环节 |

- 最优组合（LeanSearch v2 同构）：**粗筛（BM25 宽网 top-50）→ LLM 精读挑选（50 条一行摘要中挑 2-3 篇读全文核实）**。正确性 = LLM 判断兜底；速度 = 只读 2-3 篇全文；成本有界。

## 2. 端到端审视结论（四层）

### 检索层（问题最重）

1. 四条检索路分裂：grep（子串）、note_search（子串+tag，无排序）、note_retrieve（hook 打分，只看记忆卡）、召回注入（最新消息原文对四类语料排序）——AI 靠 AGENTS.md §5 手写路由表选工具，查一个主题需笔记与记忆分两次查；
2. note_search 无相关性排序，命中按文件序返回；
3. 召回注入每轮无条件烧 2200 字符，且与工具检索是两套不相干的排序；
4. hook 卡只覆盖记忆，普通笔记不参与策略检索。

### 关联层

5. 关联全靠三写自律（wikilinks/related/source）；实测 vault records/index.md 为空——三写第 2 步在真实使用中未落地，关联层半失效；
6. 无确定性断链检查（source 悬空、related 断链、索引缺行）。

### 提取层

7. 提取 = 模型收尾三写（prompt 自律）；实测 episodes/memos 质量高，但记录层零产出——「细→粗」链条断在第 2 环；
8. 审计 pass 管 hook 统计，不管结构校验（缺 source/缺索引行）。

### 整理层（健康，保留）

9. 五层结构、每日体检、hook 统计回写、归档：不动。

## 3. 目标架构：统一入口 + 粗筛-精读

```
┌─ 统一索引（本地，毫秒构建/更新）──────────────────────┐
│ 每篇一个 passage：笔记 + 记忆卡 + 备忘录 + 主题/事件行   │
│ = 标题 + tags + 摘要/首段 + hook 字段 + source/related    │
└────────────────────────────────────────────────┘
        │ ① 粗筛：BM25 top-50（0 token，毫秒级）
        ▼
  50 条一行摘要（title + 一句话，有界 ≈1-2K token）
        │ ② 精读：AI 在生成内挑 2-3 篇读全文核实 ← tokens 花在这里
        ▼
  不够/全不适用 → 改查询重试一次 → 仍无 → 明说没有（空是信号）
        │ ③ 顺链：读到的笔记/卡沿 related/source 链扩一步
        ▼
  ④ 可选扩召回：本地 bge-small-zh hybrid；独立 LLM 重排为备选开关
```

### S1 统一索引与统一入口

- 新工具 search（暂名）一次覆盖笔记+记忆卡+备忘录+主题/事件；返回带来源类型标注的统一 top-k；
- AI 不再背路由表；hook 命中统计（uses/last_used）迁移到 search 的命中记录，反馈闭环不丢；
- 索引按 vault 文件 mtime 指纹增量重建（现有 recall 缓存的机制复用）。

### S2 粗筛：BM25

- 标准 BM25（k1=1.2, b=0.75）+ 现有分词（ASCII 词 + CJK 二元组）；hook 字段加权（techniques/applications 命中加分）；
- 零 token、零部署、毫秒级；比现状 overlap 系数严格更强（词频饱和+长度归一）。

### S3 精读：LLM 在生成内挑选核实（正确性核心）

- search 返回 top-50 的一行摘要列表（有界 token）；AI 在自己的推理里挑 2-3 篇读全文并逐篇判「适用/不适用」；
- 全部不适用 → 换查询重试一次（有界）；仍无 → 明说没有——LeanSearch 的「空集是信号」；
- 这是 AgentIR「推理联合查询」+ LeanSearch「reranker」的零额外 API 调用版本：挑选发生在主生成内。

### S4 可选扩召回（按探针结果启用）

- 本地 bge-small-zh（约 95MB，transformers.js，CPU 毫秒）：hybrid = 0.5×BM25 + 0.5×cosine，覆盖「策略相似词面不同」漏检；
- 独立 LLM 重排（每次检索 1-2K token）：仅当用户明确要求更强效果时启用。

### S5 注入改为按需导航

- 每轮只注入极简「主题地图 + 最新事件标题」（几百 token），让 AI 知道「有什么」；细节全部走 search；
- 替换现在的 2200 字符无条件召回注入——更省、且与工具检索同一排序。

### S6 关联顺链与提取校验

- 精读环节顺链：读到的笔记/卡沿 related/source 链扩一步（一次 search + 顺链读替代多次 search）；
- 审计 pass 增加结构校验项：records 缺 source、索引缺行、related/source 断链 → 注入体检报告，三写从纯自律变成「自律+体检兜底」。

## 3.5 架构边界：与记忆系统的关系（写读分离、文件契约耦合）

- **不合并、也不完全独立**：写路径（三写/体检/统计回写/归档）与读路径（索引/排序/精读）保持独立生命周期与故障域；两个系统只通过文件级接口耦合。
- 接口 ① 数据：检索系统把 `.deepseek/memory/**` 卡片当作「带类型的文档」纳入统一索引（与笔记同一管线，查询一次同时命中笔记与记忆）；检索**只读不写**记忆文件，安全边界不变。
- 接口 ② schema：hook frontmatter 归记忆系统拥有（模板 + 审计维护），检索系统消费（passage 组装 + 字段加权）；schema 变更 = 两系统唯一协调点，版本化。
- 接口 ③ 反馈：检索命中 → `cache/retrieval-stats.json` → 体检读统计并回写卡片 `uses/success_rate` → 检索读作先验。数据流成环，代码零互相调用（现状已如此，v2 保留）。
- 接口 ④ 推送：profile/topics 导航注入与 dialogue 线索由记忆系统注入 prompt（让 AI 知道「有什么」）；「拉取」全部走统一 search。
- v2 迁移点：note_retrieve 的 hook 打分与命中统计并入 search；算子硬过滤降级为可选参数；三写、体检、归档、捕获策略完全不动。

## 4. 成本模型（本 vault 规模）

| 环节 | token | 时延 |
|---|---|---|
| 统一索引构建/增量更新 | 0 | 毫秒-百毫秒（仅文件变化时） |
| 粗筛 BM25 top-50 | 0 | 毫秒 |
| 50 条一行摘要列表 | 约 1-2K | 即注入 |
| 精读 2-3 篇全文 + 判断 | 2-4K | 正常生成 |
| 按需导航注入（替代 2200 字符召回） | 数百 | 0 |
| **每轮合计** | **约 3-6K（有界）** | 本地毫秒 + 正常生成 |

对比现状：四路分裂检索 + 无条件 2200 字符注入，token 不省、注意力分散、笔记与记忆两查。

## 5. 兼容与迁移

- 旧工具去留：search 取代 note_search 与 note_retrieve 的查询职责（hook 统计迁移）；note_links 保留为顺链专用；grep 保留为底层兜底；
- 记忆五层/hook schema/体检/统计回写/安全边界不动；
- 无 hook 旧卡片参与统一索引（BM25 覆盖全文），零迁移。

## 6. 实施顺序

1. S1+S2：统一索引 + search 工具 + BM25（回归断言：相关>无关、词频饱和、长度归一、kind-aware 组装）；
2. S3：精读协议（AGENTS.md 重写检索/证明章节 + 空结果语义 + 重试上限）；
3. S5：按需导航注入（删 2200 字符无条件召回，补导航摘要）；
4. S6：顺链协议 + 审计结构校验项；
5. 部署 → 用户手动探针（5-10 题，含换说法策略题）→ 不过关则 S4（embedding/LLM 重排）。
