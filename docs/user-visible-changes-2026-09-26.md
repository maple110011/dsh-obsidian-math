# 这次改了什么：用户可见改动一览（2026-09-26）

> **这份文档是给你（使用者）看的**：只讲你会在界面与对话里看到的变化、什么时候生效、以及代价。
> 工程细节与理由在 [`docs/changelog.md`](changelog.md)；每条的技术背景都能在那里查到当天那一节。

## 先做一件事：重启

**重启 Obsidian（重载本插件）与 3080 那个 dsh。** 插件产物 `main.js` 已更新（761,115 字节），两层 profile
里的引擎文件与"预设声明"也换了位置。不重启的话，下面标注"重启后生效"的项看不到。

## 一、对话里能看到的（重启后立即生效）

1. **记忆索引每行尾多一个证据标记**：`✅` 你确认过 / `⚖️` 与他人互证 / `❓` 只出现过一次。
   没有 `verified` 字段的卡一律算 `❓`（最弱证据不会看起来最干净）。
   *为什么*：此前这套分级只在面板上显示，模型看不到 —— 实测里**一条 AI 单源卡会排在你自己确认过的卡前面**。
2. **注入的层标题会明说"这是笔记里的说法，不是事实"**：个人画像 / 记号体系 / 主题索引 / 记忆记录摘要四处。
   文件里没有你确认过的痕迹时，标题还会多一句"其中含 AI 归纳，未经你逐条确认"。
3. **互相矛盾的两条会被当场标出来**：两条卡的一行结论极性相反（一边"要/不要"）且指向同一个解法时，
   注入里两行都会带 `⚠️与[[另一张]]矛盾`，体检清单里也会列出来，并注明"**只报不改，需你判断信哪条**"。
   判据刻意做窄（宁可漏报不误报）：同一 signature + 极性相反 + 至少共享三个 2-gram。
4. **体检清单先报"可能误信"的项**：`unverified`（单源且陈旧）与待重审移到所有"改进类"清单之前 ——
   清单在 1200 字符处会截断，而这两类恰恰是唯一"防误信"的；强/弱/未用只是"改进"。
5. **面板报错不再误导**：以前"路由没挂"（404 + 空响应）会显示成
   `SyntaxError: Unexpected end of JSON input`；现在会告诉你是哪条路由、HTTP 状态多少、以及"空响应 ——
   路由可能没挂上"。

## 二、设置里能看到的

6. **两个新开关**（此前**只能手改文件**）：
   - **记忆总开关（enabled）**：关掉后不注入记忆、不体检、不扫对话索引；记忆文件与缓存原样保留，
     笔记工具（`note_recall` 等）照常可用。
   - **体检自动归档低效用卡（autoArchive）**：体检把「零使用 + 陈旧超过 90 天 + 不是你确认过的」卡移进
     `.deepseek/archive/`（可找回）。注意它与同页那项"**启动时自动归档旧事件**"不是一回事：后者归档的是
     对话事件（episodes），存的是插件自己的设置。
7. **描述瘦身**：最长的一条（皮肤中心）从 **633 字符降到 106**，其余 39–93。删掉的是更新记录与实测数字
   （"自 dsh-web-all 0.3.20 起…""6 次点击里 3 帧超过 50ms…"），保留的是"它做什么 / 代价是什么 / 要不要重启"。
8. **记忆类设置改为走服务端**（记忆总开关、体检自动归档、四个捕获策略档、自动保存对话、注入预算档位）。
   - **代价（要说清）**：改这些设置现在**要求 dsh 服务在运行**。服务没起来时你会看到一条点名路由与原因的
     提示（例如"改动没生效 —— /memory-panel/config-flag HTTP 0：空响应 —— 服务可能没起来"）。
   - **收益**：以前同一个动作有两条写路径（面板走受守卫的 HTTP、设置页进程内直写），现在统一成一条，
     失败**会说出来**而不是改了却毫无效果。读取仍留在插件内（读文件不产生副作用）。
9. **`config.md` 模板补上了 `budget` 说明**：以前你用设置页改过"注入预算档位"之后，`.deepseek/config.md`
   会多出一个模板从没解释过的 `budget:` 键。**已有 vault 的现有文件不会被动**，只有新建/重新初始化的
   vault 会带着这行说明。

## 三、已经修好的一类故障（你不一定会看到，但它真实发生过）

10. **"所有会话突然报 agent-preset/not-found"**：预设声明原来放在一份**插件每次起服务都会重写**的文件里，
    只要插件比 profile 旧一点，声明就被无声擦掉。现在它住在 profile 自己的层（没人会重写），
    并且**存量 profile 会被自动补上**（只增不改，不动你手改过的内容）。

## 四、已知没做、以及仍要你决定的

- **单源老化降权**（让陈旧且未核实的卡在检索里降权）：没做。它会移动既有排序，必须先跑检索门槛复核
  （"命中数不降且排名均值不升"），是否上由你定。
- **六个"只能改文件"的开关里还有四个**：`dialogueIndex`（跨会话问答线索）、`reminders`（备忘录提醒）、
  `audit`（每日体检）、`captureSubagents`（是否也保存子代理会话）。它们在 `.deepseek/config.md` 里，
  模板带逐项说明；要不要也做成界面开关由你定。
- **AI 自家归纳的产物默认停在 inbox**（要进 records 必须你确认）：暂缓，等出现"模型把 AI 归纳当成你的原话"
  的实例再上。
- **薄记忆模式**（注入预算再加一档）：不做。实测基准 vault 注入 4088 / 硬上限 18000，还很宽裕。
