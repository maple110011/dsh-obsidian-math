# 成本基准：单题 tokens 对照（存档，2026-08 测量）

> **状态：已停用口径（历史档案，不再维护）。** 本文件保存**一次实测**的原始数字与出处。它**不再是**产品的活跃验收声明——两个 README 的「验收记录」里那句话已于 **2026-09-18** 按用户决定移除（用户原话：**「那个成本基准可以存档了，目前不需要它」**）。本文只做证据存档，**不要把它当作当前状态或当前承诺引用**。

## 1. 被测的东西

**一道题、一次对照**：同一道数学提问，分别在「旧系统」（无本项目的分层记忆注入）与「新系统」（本项目的记忆系统）上各问一次，比较**计费 tokens**。

- 这是**单题单次**的观测，不是套件、不是重复测量、也不带误差估计。它**不能**外推成"本记忆系统平均省 x% tokens"。
- 它测的是**上下文成本**（注入 + 检索开销），不含答案解析质量。

## 4. 证据边界（为什么它只配当"一次观测"）

这一节记录**当时就已经知道**的几个限制。它们是"停用口径"的一部分理由，也提醒后来者：想恢复这个测量，要连**测量方法**一起重建，而不是把那两个数字重新抄回去。

- **没有可复现的测量脚本**。全仓没有任何脚本、用例或 baseline 绑定这两个数字——它来自一次人工对照运行。你无法重跑它、也无法验证它。
- **与 E2E 的 token 计量已知损坏**（`docs/project-assessment-2026-09-10.md` §2 第 11 条）：当时 `scripts/qa/e2e.mjs` 的 **token 计量恒为 0**，原因是它只读会话格式 V3 里**已被移除**的 `assistant/chunk` usage 事件——而 `docs/memory/benchmark.md` §5 恰恰把"tokens 从 `assistant/chunk` 的 usage 里取"写成了成本记录的设计。所以**同一个仓库里，"成本怎么量"这件事本身当时是坏的**；上面那两个数字来自别处的口径（dsh 的计费视图），不在 QA 套件里。
- **`baseline.json` 只写不读**（`docs/memory/benchmark.md` 顶部注、`handoff.md` §7）：即便当年跑过 E2E，"跨次对比成本涨跌"也从未真正生效。

## 5. 要恢复这项测量，需要什么

如果要重新把"成本"变成可引用的验收口径，最小可复现版本是：

1. 一道**固定的**题（写进 `scripts/qa/cases.json` 那样的用例，而不是记在文档里的一句话）；
2. **可重跑的**对照（有/无记忆注入各一次），并且每次都记下模型、生成参数与计费口径；
3. 修好 token 计量（读当前会话格式里真正带 usage 的事件，而不是已移除的那一种）；
4. 至少重复几次，报**分布**而不是单个数字；
5. 把结果落进 `baseline.json`，并让某个守卫真的**消费**它（否则它又会变成一个只写不读的死产物）。

在那之前，本文的数字只能作为**当时观察到的数量级**参考。
