## [0.7.8] - 2026-09-18

> 本版主要包含四个方面：**记忆的治理闭环**（净增益、依据链与失效级联、接地门、状态即权限、边界随否决收窄），**记录纪律**（体检台账、索引行说明下限、卡片尺寸上限），**写入的诚实性**（预算截断自报、破坏性写入原子化且失败必进报告），以及**注入预算档位、文献库索引状态与检索成本探针**。另修掉一个会让适用边界静默失效的缺陷，并更正几处文档错误陈述。

### Added

- **记忆：治理闭环（净增益 / 依据链 / 反模式 / 状态即权限 / 边界收窄）**
  - **`hook.gain`（−1 / 0 / +1）**：`uses` 数的是"被检索出来几次"，不等于"帮上忙"。`gain` 只由你显式点的 ✅（+1）/ ❌（−1）推出，无反馈则不写这一行（中性）。**负值会把该卡排到未评级卡之后**——这是 `harmed`（单侧计数、不进排序）做不到的。
  - **`depends_on`（有方向的依据链）**：与无方向的 `related` 不同，它让"某张卡的依据变了之后，哪些卡需要重读"变成体检可以查出来的事（体检新增「下游待复查」段）。同时新增「结构枢纽」段（被多张卡引用的卡单列，提醒改动影响面）。
  - **拒绝即收窄适用范围**：你点「本次场景不适用」时，插件会把本次检索的上下文特征追加进该卡的 `not_applicable_when`，于是**下次同类查询会直接排除这张卡并说明原因**，而不是只把成功率降一点。「❌ 这张卡有错」**不会**改边界（那是内容判定，不是适用范围判定）。
  - **`decision_guidance`（建议 / 避免，成对、各带证据）**：`note_strategy` 渲染成「✔ 建议 / ✘ 避免」。只写"该怎么做"记不住教训，成对写才能把一次失败固化成可迁移的判断。
  - **策略卡分出「候选」与「可依据」**：`note_strategy` 把 `status: candidate` 的卡单独列出并标明"只能当线索、不得当作已验证技巧引用"。
  - **晋升的接地门**：候选策略卡即使 uses/成功率达标，**缺 `source` 也不晋升**，体检会点名并说明"补上 source 后会自行晋升"（门只阻断，不额外索要字段）。
  - **跨场合支持计数**：同一技巧被几个**独立** episode 支撑（≥2 才算方法而非轶事）；只进体检报告，不参与晋升判定。
- **记忆：体检台账（跨次判定史）**——体检每天都会从同样的文件推出同样的建议，此前"这张卡上周报过、当时决定先不动"无处记录，于是同一张卡会被当成新发现反复报。现在每次体检把建议追加进 `.deepseek/cache/audit-ledger.jsonl`（**只由插件写、只增不改**），并在报告里**把"本次新动作"与"此前已在账、今日仍成立"分开**：历史条目只带首次出现日期与次数，**不要求你做任何动作**。判定仍归你与助手，台账只记录。规格见 `docs/memory/design.md` §8.1。
- **记忆：索引行的说明不再可以空着**——`records/` / `templates/` / `strategy/` 的索引里那句"一句话"决定读者要不要打开卡片，而此前 `- [[x]]` 或 `- [[x|?]]` 也能通过体检。现在体检会确定性检查**描述是否为空白或过短**并点名（写明该补什么：是什么 + 为什么有效 + 怎么做），**只报告、不代写**；行首不是 `[[链接` 的行会作为「索引行不合契约」单独报（这种卡按名字找不到）。
- **记忆：卡片有了尺寸上限，超限会被点名**——正文超过 **20 行**、策略卡 move 超过 **5 个**时，体检会单独报一条并说明该怎么办（拆成原子卡 / 把过程挪进事件卡 / 按触发条件排序并移出不触发的 move），**不会替你改**。上限来自实测分布（种子库正文 7–8 行、move ≤ 3），刻意宽于正常写作。
- **记忆：注入预算档位 + 设置页入口**——「注入预算」下拉框（`compact` / `standard` / `rich`）控制每次开机注入的**导航层**大小（主题/记录/模板/事件索引）。**它不限制正文**：答案内容仍由 `note_recall` 按需检索。**默认 `standard` 与改动前的数值逐字相同**，不选就什么都没变。档位写在 `.deepseek/config.md` 的 `budget`；显式写在 preset 配置里的 `budget` 优先级更高。
- **文献库：索引状态显示卡片真实状态 + 陈旧提醒**——此前索引的「状态」列取的是首次建卡时的机器默认值（恒为「未读」），而卡片跨导入是保留的，于是全库卡片其实都已蒸馏、索引却全显示「未读」。现在改读卡片；并在卡片 `研读状态` 写 `- 状态更新：YYYY-MM-DD` 时给出「已停 N 天」与陈旧提醒（未读/待提炼 ≥ 7 天、研读中 ≥ 30 天）。
- **QA：引擎探针新增「检索成本 Avg-R」**（零 token）——`Avg-R = Σ(未找到 ? 10 : 目标排名) / 用例数`，并报中位数、最差名次、名次分布。命中率把"第一个就对"和"翻到第 7 个才找到"记成同一个分数，这个数字把差别量出来。只报告、不做断言。
- **门禁 38 → 41**：中英 README 配对守卫 `check-readme-pair.mjs`（只改一侧就红，并指出是哪一侧被编辑；`--write` 重新记录，`--selftest` 8 项变异）、文献库索引逻辑 `test-lit-import.mjs`（10 项，进程内）、陷阱条数与门禁总数守卫并入 `check-doc-counts.mjs`。

### Changed

- **记忆：破坏性写入不再可能"无声失败"、被预算截断时会自报**——自动归档以前把每个错误都吞掉，重命名或索引写入失败时报告照样说"已归档 N 张"。现在索引改写走**临时文件 + 读回校验 + `.bak` 备份 + 原子替换**（任一步失败，原文件一字不动），失败作为"降级"写进体检报告并说明卡片是否已移动、可据 `.bak` 修复。超预算的注入段落此前只以结尾一个 `…` 表示，"原文本来就这样"与"被截了"看起来一模一样；现在截断处写明**原文总长度**（`……［截断：全文 N 字符］`），标记不占预算、不改变各层实际注入量。
- **排序对插件专有字段的脏值免疫，字段所有权显式化**：`success_rate: 5`、`uses: -3`、`gain: 99` 这类手改值会被钳制在量纲内，不会把排序先验推飞；同时文档与模板写明哪些字段归模型写、哪些只由插件写。
