# 项目重构蓝图（2026-10-01）：从「个人笔记插件」到「数学/统计学习与科研插件家族」

> **本文是什么**：一次**前提置换**之后的重新设计。前提从"仅 Obsidian 插件 / 极低成本 / 尚未 dsh-Obsidian 解耦"换成"**dsh 插件家族 / 成本可放宽（只需针对性优化）/ 环境由用户自备，插件只负责声明与指引**"；**现有个人笔记插件降级为新项目中的一个功能**。
> **本文回答两件事**：① **逐条复审历史决定**——哪些是"当初约束的产物"可以改，哪些是**真正的不变量**不许动；② **家族靠什么协议协作**——跨插件接口、数据契约版本化、第三方工作流贡献的治理、环境依赖的声明与指引。
> **与既有文档的关系**：这是 [`plugin-family-assessment-2026-10-01.md`](plugin-family-assessment-2026-10-01.md)（四问评估）的**续篇与修正**。那份报告把"不调模型、不持库、不引新运行时、不做 Lean、不挂 shell"判成了 **(a) 产品红线、与架构无关**——**这个判断是错的**，错在把"成本/范围产物"当成了"原则"。本文用一手证据纠正它（§1）。
> **状态**：前提与复审已定稿；协议设计为**提案**（可被讨论，但每一处都标了"已存在（引证）"还是"我的提案"）。**未动任何代码。**

## 0. 一页结论

| # | 结论 |
|---|---|
| 1 | **你的判断成立，而且有一手证据**：这些"红线"的出生环境确实是"仅 Obsidian 插件 + 尽量便宜"。**成本曾是一等约束**——专门有 `docs/archive/cost-benchmark-2026-08.md` 记录"17 万 → 2.5 万 tokens"的对照，而该文 §4 自陈**当时"成本怎么量"这件事本身是坏的**（token 计量读的是已被移除的事件、`baseline.json` 只写不读）。⇒ **"贵"曾是拒绝理由，而"多贵"从未量准。** |
| 2 | **最强的单条证据是项目自己提过、后来静默降级的那一条**：2026-08 第 1 轮评估的 **P0-2** 就是「**异步确定性固化流水线**：turn/session 结束钩子触发独立固化 pass（候选生成 → embedding 去重 → schema 校验 → 写 episode 引用）+ 会话结束『记忆 diff』」（`docs/memory/assessment.md:54`）。第 2 轮把它改写成"ISM 七机制的本土化确定性维护 pass"（`:85`），最终实现成**跑在 preset 里、每轮路径上**的每日体检。**"异步 + 宿主侧"那一半被丢掉了，且没有任何地方记为放弃。** |
| 3 | **范围假设也有字面证据**：多智能体蜂群与并行证明搜索被否的原话是「**我们场景是单用户数学学习**」（`docs/memory/references.md:194`）——正是"当时只考虑个人笔记"。**新构想直接拿掉了这条理由。** |
| 4 | **但有一半不是成本问题，必须保。** 同一批早期文档把另一些写成**优点/保留项**（`docs/memory/assessment.md:35-39`）：证据链与版本化"**从不静默删除**"、fail-closed、防打扰（捕获须同意 / 提醒限频 / `note_create` 拒绝覆盖）。**这些与贵不贵无关**——§3 是它们的清单。 |
| 5 | **复审结论（§1）**：L1–L13 里 **4 条是纯成本/交付（B）、2 条是纯范围（C）、3 条是"价格的一半可放宽、原则的一半要保"（B/A 混合）、4 条是不变量（A）、1 条是实测证据（D）**。最该改的是 **L9（不做 Lean）与 L10（不引工具链/二进制/新运行时）——它们在新授权下基本整体作废**，但作废的方式不是"拆掉"，而是**转成"声明 + 指引 + 降级"契约**（§5）。 |
| 6 | **协议的核心不是"接口多好看"，而是三份"契约"**：**能力服务契约**（跨插件怎么互相看见）、**数据契约**（vault 格式怎么版本化到第三方能依赖）、**环境契约**（要什么运行时、缺了怎么降级）。**三份都可借现成先例**：dsh 自己的**会话格式迁移模型**（`dsh-session-format-v0-to-v1` … `v3-to-v4`，**一跳一个迁移包**）就是数据契约版本化的模板（§4.2）。 |
| 7 | **重构的形状**：**1 个仓库 = 1 个契约包 + 1 个核心功能包 + N 个能力包 + 2 个 profile（study / research）+ 可选聚合包**。现有笔记插件成为**核心功能包**，而不是全部。**最先要建的**不是任何能力包，而是 **`@dsh-math/contract`（契约包）**——没有它，第三方贡献无从谈起。 |
| 8 | **成本放宽不等于可以不算账**：既然目标从"便宜"变成"质量"，**度量本身从可选项变成承重项**（原 L6 的一半要反转：不跑 token 型 benchmark 曾是被批准的省钱决定，现在"质量/成本可测"是改进的前提）。见 §3.4。 |

## 1. 历史决定复审（按"当初约束 vs 新约束"重新分类）

### 1.1 分类口径

| 类 | 含义 | 处置 |
|---|---|---|
| **A** | 真正的数据安全 / 正确性 / 可审计性原则 | **保**（重构后仍是不变量） |
| **B** | 成本 / 交付形态优化 | **可放宽**（用户已授权；只保留"针对性优化"要求） |
| **C** | 范围假设（"个人笔记、单用户、非科研"） | **可改**（新构想已改口） |
| **D** | 实证结论（实测为负） | **是证据，不是成本**——语境变了要**重测**，**不得当"已解决"直接推翻** |
| **E** | 当时的技术限制（"只能跑在 Obsidian 侧""preset 够不着宿主服务"） | **必须对 dsh 0.2.0-rc.2 逐条复核** |

### 1.4 最该反转的六条：代价与验收判据

> 只有"改成什么"是不够的——每条反转都要说清**要付什么代价**、**怎么算做成**。验收判据一律写成**可执行断言**（不是"看起来对"），并优先给"该报错时确实报错"的变异验证。

| 反转 | 改成什么 | **代价** | **验收判据** |
|---|---|---|---|
| **L10 作废**（不引工具链） | 转为"声明 + 指引 + 降级"环境契约（§4.4/§4.5） | 需要新建**三样交付物**：每包 `dsh.requirements`、一个 doctor 技能、家族自检命令；并要为"缺环境"写降级分支与其测试 | ① 故意不装 Lean ⇒ 依赖它的能力**降级并在输出里明说**（不是崩、不是静默空结果）；② 家族自检能列出每个成员的环境状态；③ doctor 技能在**缺失**与**存在**两种情形下都给出可执行指引 |

| **L6 前半反转**（要度量） | 建可复现的质量/成本基准 | 要修好当前的**坏度量**（token 计量读错事件、`baseline.json` 只写不读），并写固定用例 | 照 `cost-benchmark-2026-08.md` §5 的五个条件：固定题 / 可重跑对照 / 修好的 token 计量 / **报分布不是单点** / 有守卫**真的消费**它。**缺任一条就不算建成** |
| **L3 拆半**（research profile） | study 不动，research 放宽（显式 opt-in） | **两个 profile 要各维护一套姿态与测试**；且权限 preset 是闭表 ⇒ 放宽只能改 profile 那一行的 config 或换 profile | ① study profile 的 fail-closed 断言**一条不减**；② research profile 的放宽项**逐条可查**（哪些工具/网络/subagent 开了）；③ 从 study 切到 research **不需要改任何包**，只换 profile |

## 2. 重构后的形状：现有插件成为"一个功能"

### 2.1 目标结构

```
仓库（= 家族）
├── packages/contract/            ← 【最先建】契约包：数据契约版本 + 服务接口 + 命名规则 + 家族清单
├── packages/memory/              ← 现有笔记插件成为它（核心功能包，唯一写 .deepseek/memory/**）
├── packages/verify/              ← 能力包（形式化 / 反例 / 等级对账）   [需要外部工具链]
├── packages/compute/             ← 能力包（Python 计算 / 可复现 / 渲染） [需要 shell]
├── packages/teach/               ← 能力包（教学闭环 / 复习调度）         [需要模型]
├── packages/research/            ← 能力包（成果银行 / 分工式多智能体）   [需要 subagent]
├── profiles/study/               ← fail-closed（现状姿态不动）
├── profiles/research/            ← 放宽姿态（shell / 网络 / subagent / MCP）
└── (可选) packages/all/          ← 聚合包（一键装齐）
```

**三条单位纪律**（来自 dsh 0.2.0-rc.2 的实测结论）：

1. **扩展单位是「插件行 + 补丁层」，不是"包"**——一个包可同时是 host 插件 + bundle + preset 提供者 + client 半个 + 技能目录。
2. **"多个模式"出多个 preset 行，不要多出包**；**"不同权限档"出不同 profile**（权限表是闭表）。
3. **跨包只经 host 服务、事件与数据契约耦合；绝不 import 另一个包的源码**——否则就是把"引擎三份"的耦合复制成"N 份清单"。

### 2.2 为什么先建"契约包"

第三方要贡献工作流，前提是**有一个可以依赖的稳定面**。当前仓库的"契约"散在 `dsh/preset/profile-contract.mjs`（安装面）与 `docs/memory/design.md`（数据面），**没有版本号、没有类型、没有兼容承诺**。契约包要装四样：

| 内容 | 作用 |
|---|---|
| **数据契约**：`.deepseek/**` 的 schema + **版本号** + 兼容规则 | 让第三方能安全读写记忆，也让主人能演进它（§4.2） |
| **能力服务接口**：service 名、方法签名、返回形状、版本字段 | 让能力包互相发现与降级（§4.1） |
| **命名规则**：包名 / 行 id / 工具名 / 技能目录 / storage domain | 让多个包共存不撞（§4.3） |
| **家族清单（机器可读）**：成员、cohort 下限、每条契约的当前版本 | 让门禁与自检有一个权威来源 |

## 4. 家族协议设计（提案；每处标注"已存在"或"我的提案"）

### 4.1 跨插件协调：能力服务契约

**dsh 实际提供的机制**（已存在，引自实装 0.2.0-rc.2）：

| 机制 | 性质 | 家族可以依赖什么 |
|---|---|---|
| `ctx.inject([...], cb)` + cordis 服务 | **加能力、可并存** | 用 `ctx.get('x')`/inject 发现服务；**缺失时降级** |
| `@deepseek-ai/dsh-scope`（`bindScopeParent`/`createScope`） | 作用域链 | preset 行挂在同一棵树的 standing scope ⇒ **host 服务对 preset 可见** |
| 注册表式服务：`ctx.tools` / `ctx.skills` / `ctx.commands` / `ctx.webServer` / `ctx.storage` / `ctx.storageDomain` / `ctx.webhookRuntime` / slots | **加能力、可并存** | 多个包各自注册；**这四类是新能力最自然的落点** |
| **单实例 seam**：`ctx.jobs` / `ctx.spillStore` / `ctx.compaction` / `ctx.sessionQuery` search / `ctx.workflowEngine` / `ctx.llm` 路由 | **一个 context 只有一份实现** | **换整包**才动它；家族最多指定一个实现者 |

**提案：能力服务契约（`mathFamily` 形状）**

```
服务名：math<Capability>（如 mathMemory / mathVerify / mathCompute / mathBank）
必须导出：
  apiVersion   : 整数（服务接口版本，破坏性变更才 +1）
  dataContract : 字符串（它读写的数据契约版本，见 §4.2）
  方法         : 一律 async，接受可选 AbortSignal；
                 不可用时不抛异常，返回 { ok:false, reason:'unavailable'|'degraded', detail }
```

四条规则：
1. **发现即降级**：`ctx.get('mathVerify') === undefined` ⇒ 能力不存在，**不是错误**；调用方必须走降级路径并在输出里**明说**降级（沿用本仓库 `degraded` 的既有纪律）。
2. **不互相 import 源码**（第 2.1 节纪律③）。跨包类型定义只从**契约包**来。
3. **能力包之间不建立硬依赖**：A 需要 B ⇒ 通过服务 + 缺失降级；**不写进 `dependencies`**（写进去就等于把家族变回一个巨型包，且失败会互相拖垮）。
4. **单实例 seam 的归属写进家族清单**：谁实现 `ctx.jobs` 的后端、谁实现 search，只能有一个，且要在清单里声明。

### 4.2 数据契约版本化：**借 dsh 会话格式迁移的模型**

**现成先例（已存在）**：dsh 自己把会话日志格式版本化，并**一跳一个迁移包**：
`@deepseek-ai/dsh-session-format` + `dsh-session-format-v0-to-v1` / `v1-to-v2` / `v2-to-v3` / `v3-to-v4`（本机实装可列）。

**提案：把同一模型套到 vault 数据契约上**

| 要素 | 设计 |
|---|---|
| **版本住在哪** | 单一位置：`.deepseek/memory/.contract.json`（含 `version` + 写入者 + 时间）。**卡片 frontmatter 不承载契约版本**——否则每张卡都要迁移 |
| **谁是写入者** | **只有核心功能包**（`packages/memory`）可以提升版本号；其他包**只读**、按自己声明的 `supportedVersions` 断言 |
| **兼容规则** | ① **读者必须容忍未知字段**（忽略而非剥除——本仓库在 `setTopField` 上已经踩过一次"改写时吃掉内容"）；② **写者不得静默升级**，只在显式迁移步骤里升；③ 遇到**更高的未知版本**：**拒绝写入并报告**，不要猜 |
| **迁移形态** | `migrations/<from>-to-<to>.mjs`，**一跳一个文件**，按序组合；**幂等**；**保留原件**（写成 `.bak/` 或归档，符合"永不硬删"） |
| **门禁** | ① 每个"读"点都必须声明支持版本；② 每个迁移跳点都要有 fixture 与断言；③ 迁移必须**幂等**（第二次运行是 no-op）；④ **迁移后原文仍在**（这条把不变量 2 变成可执行断言） |
| **第三方** | 贡献者声明 `dataContract: "<它依赖的版本>"`；契约包提供该版本的**只读 fixture**，让第三方能在不接触真实 vault 的情况下测试 |

### 4.3 第三方贡献治理

**可直接照抄的部分**（dsh-web 已在做，`docs/plugins.md` + 收编政策）：
- **命名空间**：npm scope、loader 行 id 前缀、工具名、storage domain 名**全部加家族前缀**，让"聚合装"与"单装"共存；
- **版本下限**：每个包（**含模板**）声明 `dsh.engines.dsh` **与** `peerDependencies["@deepseek-ai/dsh"]` 同值、**只认 `>= X.Y.Z[-rc.N]`**，且**不得低于家族 cohort 下限**；CI 强制；
- **收编红线**：活跃上游 ⇒ **不搬代码**（fork 到家族组织或当依赖）；收编需"无活跃上游 / 已停更 / 作者授权"，且必须 `git subtree` **保历史** + **保 LICENSE 与署名** + 记录来源与迁移日期；**无 LICENSE / 未授权 / 版权不明 ⇒ 一律不收编**。

**为家族新增的部分（提案）**：

| 项 | 规则 |
|---|---|
| **贡献者必须声明三件事** | ① 它依赖的数据契约版本；② 它需要的**环境**（§5）；③ 它需要的**权限档**（study / research） |
| **门禁（家族级，一条命令）** | ① 行 id 前缀正确；② 版本下限 ≥ cohort 下限；③ **静态扫描：没有跨包 import 源码**；④ 每个包有中英 README 且配对记录已更新（本仓库已有 `check-readme-pair` 的现成机制）；⑤ **装完自检**：`dsh --profile <p> --dump-config` **零 `not found`**（因为第三方行的失败**只 warn 不中断**，必须自己查）；⑥ 数据契约迁移有 fixture 且幂等 |
| **改数据契约 = 特殊审批** | 任何会改变 `.deepseek/**` schema 的贡献，必须同时交付：**迁移 + fixture + 兼容声明**，并由契约 owner 复核——因为它影响**所有**成员与用户的既有 vault |
| **所有权** | 每个包一个 owner（CODEOWNERS）；契约包 owner = 主人 |
| **发布通道** | npm（主）+ `dsh plugin add github:<repo>`（从源装，dsh 原生支持）+ 可选**家族索引文件**（照 dsh-web 的 `community.json` 形状：`id/name/author/repo` 必填，`description/npm/category` 可选，CI `--check`） |

### 4.4 环境依赖的声明与指引（你指定的模式）

**dsh 现状（已存在）**：`dsh.engines`/`peerDependencies` **只管 dsh 版本**；**没有**通用的"我需要 Lean/Python/R"机制。所以这是**家族自己的契约**。**现成先例**：`@deepseek-ai/dsh-sandbox-windows-acl` 是一个"**自带诊断与修复**"的技能——这正是"插件负责声明+指引"该借的形状。

**提案：四段式**

| 段 | 内容 |
|---|---|
| **① 声明（机器可读）** | 包内 `dsh.requirements`（家族约定，非 dsh 强制）：`runtime`（node/python/lean/R/tex/…）、`minVersion`、`approxDownload`、`network`(bool)、`permissionTier`("study"\|"research")、`docs`（指引路径/URL）。**声明是给人看的，不是给人信的**——真伪由 ② 查 |
| **② 诊断（技能 + 命令）** | 每个能力包**自带一个 doctor 技能**（照 Windows ACL 那个先例）：跑真实检查（`lean --version`、Python 版本、磁盘、模型文件是否存在），输出**缺什么 + 怎么装 + 装完怎么验**。**绝不自动安装**（按你的要求，环境是用户的事） |
| **③ 降级（运行时）** | **缺环境不得让插件激活失败**（dsh 的可选插件语义要求如此）。运行时统一返回 `{ ok:false, reason:'missing-runtime', detail:{ runtime, hint } }`，调用方**明说降级**而不是静默给空结果——这是本仓库反复踩过的"假绿"形态的反面 |
| **④ 引导（安装后自检）** | 家族自带一条自检命令：列出每个成员的"合约版本 / 环境状态 / 权限档 / 是否装载"，缺环境就打印 ②的指引。因为**第三方行失败只 warn**，没有这条自检，"装了但没生效"就会成为默认体验 |

**一条纪律**：**插件永不 vendored 工具链**。它可以声明"我需要 Lean ≥ 4.x + Mathlib"并给出指引，但**不替用户装**——这与"环境由用户自备"一致，也避免了安装通道把 GB 级依赖当默认。

### 4.5 一页式兼容协议（贡献者看这一页就够）

```
包名            @dsh-math/<capability>            # 家族 scope
loader 行 id    math-<capability>-*               # 前缀，避免与单装冲突
版本下限        dsh.engines.dsh == peerDependencies["@deepseek-ai/dsh"]
                形式只能是 >= X.Y.Z[-rc.N]，且 >= 家族 cohort 下限

                缺环境必须降级且明说；永不自动安装
```

## 5. 分阶段重构路线

> 每阶段：**目标 / 触及 / 验收判据 / 变异验证 / 退出条件**。原则：**先把契约立起来，再搬引擎，再加能力**；每阶段可独立回滚。

### R0 · 前提与决策（零代码）
**产出**：本文 + `docs/pending-decisions-2026-10-01.md`（把 §1 的复审结论与仍需你点头的项收在一处）。
**验收**：每个 L/N/D 项都有明确表态或"暂不决定"；门禁仍绿。**未拍板不动代码。**

### R1 · 契约包 + 数据契约版本化（**无行为变化**）
**目标**：把散在 `profile-contract.mjs` 与 `docs/memory/design.md` 的"契约"收敛成有版本号的包，并让 `.deepseek/**` 的 schema **第一次有版本**。
**触及**：新增 `packages/contract`；`.deepseek/memory/.contract.json` 与读点声明；`migrations/`（此阶段可以只有一个"v1 基线"跳点）。
**验收**：① 所有读点都声明支持版本；② 迁移幂等 + **原件保留**（不变量 2 的可执行断言）；③ `npm test` 54/54 且 `test: memory regression` 仍 427/427（**纯增量**）。
**变异验证**：① 人为把 contract 版本写成未来版本 ⇒ 必须**拒绝写入并报告**（不能猜）；② 去掉"容忍未知字段"⇒ 必须有一条断言红（因为写回会吃掉未知字段）；③ 迁移跑两次 ⇒ 第二次必须 no-op。
**退出条件**：若发现 schema 无法在不改行为的前提下描述，说明契约抽取的粒度错了，先粗后细。

### R2 · 引擎归一（纯重构）
消掉三份引擎里**机械重复**的部分（23 个同名符号 → 规范实现 + 同名 shim），Obsidian 内嵌 loader 退役（`main.js` **−76 KB**）。
**验收**：54/54 且回归断言数不变；`main.js` 逐字节重建绿；体积下降有数字。
**变异验证**：让两份实现不一致 ⇒ `check-engine-sync` 或路由回归必须红。
**退出条件**：`KNOWN_DIVERGENT` 里的 6 条若确为**有意不同**，不合并、只登记。

### R3 · 宿主侧服务化：**把第 1 轮的 P0-2 拿回来做**
**目标**：把对话索引指纹/重建移出每轮路径；宿主侧持久结果；preset 变薄读取方。**这正是项目 2026-08 自己提过又静默降级的 P0-2（`memory/assessment.md:54`）。**
**关键约束（2026-10-01 复核后修正）**：
- ⚠️ **先别自己写调度器——`dsh-schedule` 可能就够了**：`dsh-schedule/README.md:12` 原文「one-shot, fixed-rate, **daily, weekly, and cron** … **Tasks remain available after Host restart**」，`:35-37` 给出 `every_seconds`(≥60s) / `daily` / `weekly` / `cron`（五段 Vixie）四种选择器，`:26` 说明启用方式（加进 `dsh.profile.bundles`）。⇒ **R3 的第一步是评估"加一行 bundle 行"**，而不是自建 durable 后端。
  - 但有两个待查的前提（见下方探针）：它**默认不挂**（0.2.0 把自动化移进了可选 bundle `dsh-experimental-schedule-bundle`），且**疑似会话绑定**——若任务挂在会话上，"宿主级周期维护"就得另想办法。
- **`ctx.jobs` 依然不适用**（实测：非调度器、属会话、进程退出即消失，`dsh-jobs-local/README.md:32/61`）。它仍是"模型发起的长任务"的工具面租约，不是周期维护的载体。

**开工前先跑三个只读探针**（各一次，决定 R3 的形状，避免把"没查"当成"做不到"）：
1. `dsh-schedule` 在当前 profile 里**是否已装载**（`--dump-config` 查行 id）；
2. `ctx.llm` / `ctx.shell` 在**宿主平面**是否真的可见（宿主插件 `ctx.get('llm')` / `ctx.get('shell')`）；
3. `node:sqlite` 是否可用（**本轮已由作者实测：可用**，`DatabaseSync/StatementSync/Session/backup`，Node v24.14.1——此项已解，无需重跑）。
**验收**：注入字节**不增**；每轮文件 I/O 下降；**宿主侧结果与现算逐字节一致**；**宿主不可用时降级为现算且会话仍能起**。
**变异验证**：宿主结果故意过期 ⇒ 有断言抓到；宿主完全不可用 ⇒ 降级路径生效；`cacheTtlMs` 改回 0 ⇒ I/O 断言红。

### R4 · 家族骨架 + 治理 + 环境契约
**目标**：立起 §4.3/§4.4/§4.5 的机制，**此时不新增能力**。两个 profile（study 不动 / research 放宽）+ 一个能力包（建议先做**不需要外部工具链**的那个，用来验证整套协议）。
**验收**：单装 / 组合装 / 聚合装三种形态都能起；`--dump-config` 零 `not found`；家族自检能列出"环境状态 / 权限档 / 合约版本"；缺环境时**降级且明说**。
**变异验证**：① 故意制造不兼容版本下限 ⇒ 自检抓到；② 故意让某能力缺环境 ⇒ 必须降级（不是崩、也不是静默空结果）；③ 故意跨包 import 源码 ⇒ 静态门禁红。

### R5+ · 能力包推进
按 [`plugin-family-assessment-2026-10-01.md`](plugin-family-assessment-2026-10-01.md) §3.2/§5.2 的排序，且**优先做"能验证协议"的**：
先 **verify**（形式化 + 反例 + 等级对账，最需要环境契约来验证 §5 的降级路径）→ **compute**（Python/渲染，本机 ✅）→ **teach** → **research**（成果银行 + 分工式多智能体，最需要 research profile 与 §4.1 的服务契约）。
**每个能力包的验收模板**：注入字节不增 · 确定性等价断言 · **降级路径存在且可见** · 至少一条"该报错时报错"的变异验证 · 环境声明与 doctor 技能齐备。
